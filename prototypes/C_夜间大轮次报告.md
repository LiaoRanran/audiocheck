## C1 区分力检验（P0-1，`04954f0`）

### 为什么必须做

`AGENTS.md` §3.4：

> 一个阈值如果把人全判到同一侧，它就是没用的。**新加任何阈值都要跑一次这个检验。**

而本项目**此前一次都没跑过**（内核审查报告 P0-1）。

### 交付物

* `packaging/threshold_survey.py` —— 对标 `headphone-lab/src/audibility_survey.py` 的口径。
  **44 个合成语料**（临时目录，不入库），按每个阈值的两侧**定向造样**；
  逐字段报 **越阈比例 / 双向分布 / 是否只判到同一侧**；全落一侧 ⇒ 打印"**无区分力**"。
  `--strict` 有盲区则返回非 0；`--json` 落盘。
* `tests/test_c1_threshold_survey.py` —— 把普查**挂进测试**（19 秒，可接受）。
  三条判据：① 无字段失区分力 ② 截止点检出率 100%
  ③ **`Thresholds` 每个字段都在普查映射里**（防"加了阈值但普查没跟上"）。
* `docs/thresholds.md` —— 总账（区分力实测表 + C2 出处占位）。

### ★ 关键发现：第一轮报的 5 个"无区分力"**全部是语料造错**

| 字段 | 第一轮 | 真因 |
|---|---|---|
| `bit_gap_warn` | 全落一侧 | **量化在电平归一化之前** ⇒ 归一化乘非 2 的幂的因子，**把低位重新填满**。分析器把"24bit 装 16bit"**正确**读成了"真 24bit"。 |
| `width_narrow_db` | 全落一侧 | **反直觉**：`width_db = 10·log10(side/mid)`，`side=(L−R)/2` ⇒ **让 R 变小并不缩小 side**。`R=0.01L` 时 width ≈ 0 dB，**根本不是单声道**。近单声道必须 `R = L(1−ε)`（ε=0.032 → −35.8 dB）。 |
| `lra_flat` | 只有 1 个样本有定义 | **恒定电平的正弦算不出 LRA**（`lra=None`），必须给起伏（±0.4 dB 慢速调幅 → lra=0.2）。 |
| `advice_low_pct` | 全落一侧 | 白噪的频段占比是平的，`sub+bass` 到不了 60%。补 150 Hz 低通样本。 |
| `advice_upper_mid_pct` | 全落一侧 | 同上，白噪的 `upper_mid` 恒 > 15%。 |

**修完语料后：全部字段两侧都有样本**（`--strict` 返回 0）。
⇒ **立一条操作纪律**：这条判据失败时**先查语料、再查阈值**。
反过来做就是**调阈值去迎合一个造错的语料** —— 那是把测量工具往错的方向校准。

### 一个必须写清的边界

`min_drop_db` / `min_stop_db` / `cutoff_min_hz` / `cutoff_need` / `conf_slope_span`
是**算法参数**，不定义判定 —— 它们决定的是"**能不能检出截止点**"。
所以它们**不做两侧分布检验**（算法参数"全落一侧"是正常现象），只报**检出率**：
合成语料 44/44 = **100%**。

唯一一个是 `loud_war_lufs`（**一手文档**），且是**推导**而非直接规定：

> **Spotify 官方支持页《Loudness normalization》**：归一化目标 **−14 LUFS**（依 ITU 1770），
> Premium 最响档 **−11 LUFS**。取 **−9 LUFS** 是因为它比该最响档**还高 2 LU**
> ⇒ 已超出主流平台的归一化上限。

其余 **32 个全部是工程估计**。这不是失败，是**如实记账**：

* 本项目立场是"没有出处的阈值，宁可标『参考』也不标『判据』" ⇒ 这份账的第一价值是

  CD 规范（IEC 60908 / Red Book），但"≥21.5 kHz 算满带宽"里的 **21.5 是本项目留的余量**。
* **编码器截止表**（对应 `ltd`/`lossy`）本轮**检索未取到可引用的一手表格**——
  公开可得的只有社区资料与转述，按规矩**不能拿来定阈值**。与 `research.md §4` 该行"未取到"一致。

## C3 假 Hi-Res 盲检测（`f5bb3b6`）—— 交付物是**负结论**

**方法**：NYCU 2017 学位论文的"差分→|·|→log→FFT→对数等距 6 段→L2 归一"特征 +
自实现逻辑回归（不引运行时依赖；SVM→LR 为系数可读可复算）。

**实测**（`packaging/fakehires_eval.py` 可复算）：训练集（粉噪/白噪）准确率 0.875 ｜
测试集（没见过的"类音乐"内容）**误报率 0.722**。

**归因**：L2 归一后的 6 段特征是整体谱形描述，被内容滚降主导；真正分开两类的是
"22 kHz 以上有没有真实能量"——**那一项 `cutoff_hz` 已在测、且更可靠**。

⇒ **判定：不构成截止点之外的增量，且跨内容类型不泛化** ⇒ `enabled = False`（理由写进
源码 docstring），代码与验证脚本保留；重开 `--only fakehires`；升格前提是**真实曲库**
误报可接受（未做）。文档落 `docs/theory.md §10` + `research.md §4`。

**三次失败都是验证集设计问题**（不是方法问题）：① 训练集 recall=0（类别不平衡 6:18 +
L2 压截距 ⇒ 类权重 + REPEATS=4）；② 测试集误报 0.806（"类音乐"源是谐波堆叠、能量只到
4.4 kHz，"genuine"标签名不副实 ⇒ 补宽带高频后仍 0.722，遂拆解出真因）。

## C4 判定颗粒度三层（`47a514f`）

**三层输出**：现象层 `phenomena`（已有，列表形态）/ 成因层 `causes`（9 类候选，
每条带证据/反证/强度/出处；证据不足并列 + "无法区分"）/ 用途层 `usability`
（10 用途 × 可用/受限/不可用/不可判 + 每格依据）。外加 `timeline`（分段问题段）
与 `boundaries`（效力边界，每次运行印一次）。

* **C4.6 conf 进入决策**：低截止 + 砖墙不足（conf < `conf_low`）⇒ `bad` 降 `warn`
  （"疑似带限…证据不足"）。`slope=None` 不改旧行为。反向保护：陡砖墙仍判 bad。
* **规矩**：成因并列不压平；用途矩阵不许成分数；判定行 `｜`→`；`；
  "未知"是正式取值（不可判）；AI 生成音频**不列**（无出处不猜）。
* **类噪守卫**（`noise_like_flatness`）：白噪 flatness 实测 ≈0.99 ⇒ 占比类证据
  （隆隆/低频缺失）在类噪内容上名不副实（实测踩过：给白噪 demo 判出"疑似磁带转录"）。
  守卫只管占比类；截止/砖墙类对噪声同样成立，不守卫。
* **自纠（砍底噪证据）**：`noise_floor_db` 是 PSD 域绝对值、随节目电平缩放
  ⇒ 黑胶/磁带的"底噪抬升"证据整体移除，只留可枚举证据（隆隆/滚降）。
* **成本记账**：timeline 逐段解码，3 分钟文件 35 段 ⇒ 管线 +0.31s（7%）。
* **口径变更 6 条**全列 CHANGELOG；demo 语料 `level` 零变化，diff 留档
  `out/_before_*` vs `out/_after_*`。
