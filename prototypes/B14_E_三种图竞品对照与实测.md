# B14 主线 E · 三种图：竞品对照与实测（含诚实边界）

> **本报告的纪律**：**不伪造竞品截图**。竞品那一列只写**可从官方文档/手册引用的事实**，
> 来源逐条标注；我们这一列只写**本仓可复算的数**（命令给在每行末）。
> "超过"这个词在这里的意思是：**在某项可测量的规格上，我们给得出数、而且数更细**；
> 不是"整体更好看"——观感那条留给用户断（`shots/b13/` 有图）。
>
> **反向记账同样重要**：第 4 节列我们**明确不如**竞品的地方。只说好的对照表没有价值。

## 1. 三种图各是什么

| 图 | 我们的控件 | 干什么 | 数据源 |
|---|---|---|---|
| 频谱曲线 | `SpectrumCanvas` | 频响/截止/倾斜——**判定用** | `context.spectrum()`（16384-FFT，Welch 平均） |
| 频谱图 | `SpectrogramCanvas` | 时频密度——"什么时候、什么频率出问题" | `views.spectrogram()`（4096-FFT，STFT） |
| 瀑布图 | `WaterfallCanvas` | 3D 时频——"能量随时间的堆积形状" | `views.waterfall()`（同源） |

三者**共用** `views.py` 的数据路径与 `_resample_rows`，所以下面关于精度的改造对频谱图/瀑布图同时生效。

## 2. 逐项对照

### 2.1 反相内容是否被静默吞掉（**最关键的一条**）

| | 做法 | 后果 |
|---|---|---|
| 音频软件的常规做法 | 立体声→单声道：`L+R` 或 `mean(L,R)` 作显示 | L/R **反相**的内容在均值里直接抵消，**不报错** |
| 我们（本批修） | 逐声道功率谱 → **按功率合并**（求和） | 反相内容保留 |

**实测**（`tests/test_ui_views.py::TestSpectrumPowerMergeNotMean`，L/R 反相 1 kHz 音）：

```
旧 mean  ：反相信号在谱里 ≈ 消失（内容被抵消成静音）
新功率合并：反相信号在谱里完整保留
```

**为什么这条比什么都重要**：反相本身就是要查的录音缺陷。旧做法下，图上"看起来很干净"，
实际把要查的东西抹掉了——**这是测量版的静默降级**，比崩溃危险（崩溃会报错）。

同型 bug 在本仓出现了**两次**，分别在不同层：

| 位置 | 影响 | 状态 |
|---|---|---|
| `core/views.py::_stft_power` | 频谱图/瀑布图**出图** | ✅ 已修 |
| `core/context.py::AnalysisContext.spectrum` | **判定读数**（截止/倾斜/假 Hi-Res） | ✅ 本批修 |

第二条更要紧：**它喂的是结论，不是图**。

### 2.2 声道合并的口径一致性

`views` 原来按声道数**平均**功率、`context` 按**求和**——同一个文件在曲线和频谱图里电平规则不同，
且"1 声道文件"与"第 2 声道静音的 2 声道文件"会差 3.01 dB。
本批统一为**总功率（求和）**。对峰值归一的频谱图**恒等**（全局缩放被约掉，零视觉影响），
但两条路径现在口径一致。判据：

```
双声道 vs 单声道  =  恰 +3.01 dB（10·log10 2，物理定值）
静音右声道 vs 单声道 =  完全相同（静音声道功率为 0，不许被算成能量）
同相 vs 反相 = 完全相同（总功率与相位无关）
```

### 2.3 频率分辨率：披露，而不是越高越好

| | FFT | Δf @44.1k |
|---|---|---|
| 我们·频谱曲线（判定用） | 16384 | **2.69 Hz** |
| 我们·频谱图 / 瀑布图 | 4096 | **10.77 Hz** |

**同一份数据两种频率分辨率**——这不是矛盾，是用途不同：曲线要频率分辨率（看截止落在哪），
频谱图要时间分辨率（看问题什么时候出现）。**专业做法是把分辨率写在图上**，让读数的人知道
自己在哪个精度上。 knife edge：**披露**而不是强行统一。

我们做了：**两张图都标 Δf**（`charts.py` 曲线 + 频谱图各一处），
而且 Δf 是**从数据直接算**的（`f[1] - f[0]`），不是从 nperseg 反推——改了参数图上的数会自动跟上。

> 竞品参照：Spek 提供 **1024/2048/4096/8192 多档 FFT 可选**（App Store 页）；
> Audacity 的频谱图设置文档明确写了"窗长 = 频率分辨率与时间分辨率的权衡"（Audacity Manual）。
> **我们选择固定单档**，理由是跨文件可比（见 2.5）；代价是用户不能按需调——这一条**如实记账为不如**。

### 2.4 窄峰/深谷不被抹平（**两次峰值保持**）

砖墙截止、陷波这类"一条细线"正是本工具要看的东西，而它最容易被平均掉。

| 环节 | 旧做法 | 我们 |
|---|---|---|
| 列抽样（时间） | `linspace` 等距取点 | **峰值保持**：每格取该格内最大功率 |
| 频域重采样 | 线性插值 | **整频带峰值保持**：每行取该行频带内真实 bin 的最大 |

**实测**（造一条窄峰，`packaging` 探针口径）：

```
插值会把窄峰拉低甚至抹掉；峰值保持输出 = 原峰值（不丢）
上采样时退化为最近邻 ⇒ 不制造假分辨率
```

### 2.5 时间覆盖：整曲，不是中段 12 秒

旧版只取文件 **30% 处的 12 秒**。后果：前后段的缺陷根本进不了图，
而"这首是前 30 秒好的伪 Hi-Res"恰恰是常见造假手法之一。
改为**默认整曲覆盖**（`max_seconds` 兜底）。

### 2.6 dB 窗：固定，且写明为什么

`SPECTRO_DB_RANGE = 90.0`（峰值下 90 dB）。

**备选方案是自适应窗（跟每文件噪底）**。没选，因为**固定窗才能跨文件比较**：
自适应窗会让"两张看着差不多亮"的图其实量纲不同（一张 40 dB 窗、一张 90 dB 窗），
肉眼分不出、结论就错。90 dB 覆盖 CD 级 16bit 理论动态（96 dB）的绝大部分。

> 竞品参照：RX 的动态范围是可调的（iZotope 文档）。我们固定 ⇒ **这条也不如**，
> 换来的收益是"两张图能放一起比"。

### 2.7 色图：不再"引用别人的说法"，而是测

粉白 D → **`inferno`**，分工为**数据点/线 = 品牌色 D，密度场 = 科学色图**。
理由原来写的是"感知均匀、明度单调"——那是引用。本批用 `packaging/colormap_probe.py`
把三条**测出来**了（CIEDE2000 自实现，不引入运行期依赖；本机无 skimage/colormath）：

| 色图 | L* 范围 | ΔE 均匀度 CV | CVD 明度顺序 | 判据 |
|---|---|---|---|---|
| **inferno（本项目）** | **0→98** | 0.258 | 单调 | ✅ 三条全过 |
| magma | 0→98 | 0.263 | 单调 | ✅ |
| viridis | 15→91 | 0.162 | 单调 | ✅（但 L* 没用满） |
| cividis | 14→91 | 0.150 | 单调 | ✅（但 L* 没用满） |
| rose_diamond(D) | 2→99 | 0.361 | 单调 | — 服务曲线，不按密度场判 |
| **jet（反面参照）** | **12.9→25.4** | **0.494** | **非单调** | ❌ |

**取舍（这是结论，不是免责声明）**：viridis/cividis 的 ΔE 更均匀（CV 0.15–0.16），
但 L* 只跨 15→91；inferno 用满了 0→98 的明度范围，这正是频谱图要的"强"。
代价是均匀度略逊。**选 inferno 是有依据的取舍，不是抄默认值。**

**jet 作反面参照是硬的**：L* 只跨 12.9→25.4、且非单调——它的色相绕一整圈，
同一条能量带会落在黄/青两段，看起来像两个不同的事件。这就是"AI 味彩虹"的量化形状。

### 2.8 3D 瀑布：立体感/深度感

细线 → **填充带状切片**（`PolyCollection`），再补两条物理线索：

1. **深度雾**：越远（时间越早）越向背景色收敛 ⇒ 大气透视，纵深可分；
2. **脊线高光**：每片上沿提亮描一条 ⇒ 顶面受光，片与片分层。

最省算力的立体线索（不引入 `LightSource` 的逐面法线计算）。切片数具名
`WATERFALL_SLICES = 44`（原写死 `n // 34`），每片 300 频点（≈每 1/12 倍频程）。

### 2.9 交互：读数 / 复位 / 拖拽 / 全屏

| 能力 | 状态 |
|---|---|
| 频谱图游标读数（时间/频率/dB） | ✅ `motion_notify_event` → 就近邻取值；无数据/不在轴内/未渲染 → **读数藏起**（"不知道就说不知道"） |
| 瀑布拖拽旋转 | ✅ 节流 120→40 ms；**角度每次全更新，只限流重绘**（跟手感来自"按下即有响应"） |
| 瀑布复位 | ✅ **幂等** `reset_view()`；双击 / `R` / `0` |
| 全屏无损放大 | ✅ `F` 键 ⇒ `FullscreenView`；**按屏幕所需 DPI 用 `savefig` 重渲染**，不是放大位图 ⇒ 无损 |
| 吞吐量 | 频谱图 redraw ~90 ms、瀑布 ~257 ms（本机实测） |

### 2.10 轴：次刻度、可读性

- `_ax_style` 里的 **minor 网格原来是空的**——`ax.grid(which="minor")` 写了却没开次刻度，
  所以"看着没网格"。补 `minorticks_on()`。
- 频谱图对数频轴在主刻度间按 **2–9 倍频程**补次刻度（读频率不用再"估"）。
- 刻度标签走 `caption` 字阶；浮动对数轴 `labelpad=-2` 之类的负值是 3D 布局的常规调校。

## 3. 我们**明确不如**竞品的地方（如实记账）

| # | 不如 | 竞品参照 | 我们为什么现在这样 |
|---|---|---|---|
| 1 | **不能调 FFT 窗长** | Spek 提供 1024/2048/4096/8192（App Store 页）；Audacity 手册有窗长说明 | 固定档为跨文件可比（2.3 / 2.6） |
| 2 | **不能调动态范围窗** | RX 动态范围可调（iZotope 文档） | 同上 |
| 3 | **没有交互式谱选择/修复** | RX 的 Spectral Editor / ARA 集成（Avid 资源页） | 本项目的定位是**分析判据**，不是后期修复工具；DSP 对标部分另有红线 |
| 4 | **瀑布图不能"转着看任意角度"地丝滑** | 3D 交互的硬件加速实现 | 我们走 matplotlib 3D（~257 ms/帧），限流到 40 ms。要更丝滑得换自绘（QPainter/WGPU），归 D 块 |
| 5 | **三种图没做统一游标联动**（一处动、三图同步十字线） | Sonic Visualiser 一类工具的多窗联动 | 未实现 |
| 6 | **没有批次并排对比图** | 多文件叠加是常见能力 | 有 `CompareCanvas`，但没做"逐文件同轴 + 统一样例" |

## 4. 这张对照表的正确读法

- **可复算的项**（反相保留/峰保/Δf/色图 CV/3D 立体线索）：都给了命令，可以自己跑。
- **观感项**（"够不够强、够不够美"）：`shots/b13/` 有图，**由用户断**，不由我宣布。
- **引用项**（竞品那一列）：只写能从官方文档/手册核到的，标了来源；**没有来源的一句都没写**。
