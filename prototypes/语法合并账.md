## 1. 高置信原则（跨软件重复出现，错不了）

- **共性-1｜文字三档，非单级**：Ableton `--tx / --tx2 / --tx3` 三档，正对我们 `text / text_dim / text_faint`。GR 也按信息层级给字色。⇒ 我们已有，保持。
- **共性-2｜深底 + 一枚强调，克制到极致**：GR 从封面只评分选一枚主导色；RX 高彩 79.2% 全在 30° 一枚暖橙上。⇒ 强调色**一枚**即够；我们的 accent 已经是玫瑰族，克制程度一致。
- **共性-3｜功能色少而各自语义明确**：Ableton 只 4 枚功能色、其余近无彩；RX 单强调。⇒ 与我们 `{accent 族, 三判定语义色相}` 结构式判据同向。
- **共性-4｜数据层才是彩的主源，UI 外壳克制**：RX 的 C>0.10（28%）主要来自数据本身、非 UI 外壳；我们 B9 data-ink 同结论。⇒ 高彩预算给数据，外壳维持低彩。
- **共性-5｜数字/西文 = IBM Plex；中文 = 思源**：Ableton 派生栈 `--ui:"IBM Plex Sans","Noto Sans SC" / --mono:"IBM Plex Mono"` —— 这正是我们已拍板的发货字体栈（OFL）。**样板屏字体不是新决策，是既有先例**。
- **共性-6｜近方角 → 仪器语言**：GR arc1=5 近方角 + Ableton 方角工具语言 ⇒ 我们 12/16px 的圆角是 web 卡片语言（见 D1）。

## 2. 候选风格（单软件独有，按服务目的决定是否学）

- **GR·内容驱动全主题动画**（整 UI 随封面换色）：播放器语义，我们**整体不移植**（底色随文件跳会让"两文件对比"不可比）；**转化的部分**：主导色可否从内容（频谱）取——须守红线④（判定语义色除外）。
- **GR·光随底色为函数 + 渐进模糊**：可迁移，转化给氛围层（见 D-light）。
- **RX·纯净数据区**（以牺牲氛围换专业可读）：与 GR 矛盾 = 核心决策点（见 §3-D0）。

## 5. 冲突登记（改口径要报数，本轮先提案不动判据）

1. **「圆角 ≤ 某值」纪律缺失**：我们此前只有 lg/xl 两档（12/16px），无 4–5px 仪器档 ⇒ 提案 `Space.radius` 增补仪器档（样板屏实测后登记数值，不取整数）。
2. **「光随底色函数」⇄「高彩面积 ≤1% / 一屏一处最强」**：光随亮度变化意味着同屏不同位置不同亮度，需重述口径（非不可解）。样板屏附实测高彩面积与亮部分布。
3. **「全 4 倍数间距」⇄ GR 非4倍数刻度**（D2）与**「阴影色」**（D3）：两版实测后 PM 定。
4. **口径"≤5 字号" ⇄ 同屏比例成组**（D4 附带）：样板屏附实测字号比例集合。

> **红线复核（不可退让）**：判定语义色（达标绿 / 不达标玫瑰）**排除**任何"从内容取色"机制；GR 的 Helvetica .otf 仅本机量测、不进发货资产；Ableton 记"社区重建·中置信"；RX 数只说明"对外视觉语言"、不当 UI 令牌。
