# audiocheck 界面 vs 专业音频工具：差距在哪

> 写这份文档的原因：用户问"跟市面上专业的比比，看差距在哪"。
> 本文的纪律是**先划清哪些有出处、哪些没有**——没有出处的判断一律标出来，
> 不混在表里冒充事实。
>
> 对比时间：2026-10-13。本文只描述"界面与交互"层面，不比较 DSP 精度
> （那部分在 `docs/theory.md` 与 `tests/test_dsp_standard.py`）。

## 1. 先摆事实：audiocheck 的界面现在有什么

| 能力 | 现状 | 出处 |
|---|---|---|
| 视图 | 8 个：总览 / 频谱曲线 / 频谱图 / 瀑布图 / 频段能量 / 多文件对比 / 批次概览 / 元数据 | `window.py` `VIEW_KEYS` |
| 判定 | 五轴 + 保真/可用性分离，每条轴带证据强度 | `core/analyzers/verdict.py` |
| 导出 | HTML / JSON / CSV / 当前视图 PNG | `window.py:1103` |
| 键盘 | Ctrl+K 命令面板（模糊匹配）+ 12 个快捷键 | `window.py:_commands()` |
| 悬停读数 | 频谱曲线有 blit 光标读数：**p95 20.1 ms** | `perf_probe.py` P1 |
| 表格 | 增量刷新单行 **0.40 ms**（200 行表） | `perf_probe.py` P12 |
| 换肤 | `apply_theme` p50 ≈ 460 ms（QSS 全量重刷） | `perf_probe.py` P7 |
| 内存 | 换肤 30 次 +32.6 MB、全流程净增 +80 MB（首轮预热后逐轮为 0） | `mem_probe.py` |
| 配色 | OKLCH 生成 + **15 条 WCAG 判据**（不达标直接抛异常） | `ui/palette.py` |
| 测试 | 20 个文件 / **249** 用例（本轮新增 20 条） | `pytest -q` |

**没有的**（`charts.py` 全文检索确认，不是印象）：

- **没有缩放/平移**。所有坐标轴范围都是代码里写死的（`set_xlim(20, nyq)` 等），
  没有 `wheelEvent`、没有 matplotlib 导航工具条。
- **没有时频选区**，因此也不可能"把结论钉在某个时间区间上"。
- **没有实时分析**：它是离线批量工具，`AnalyzeWorker` 一个文件一个文件地跑。
- **没有图例交互**：多文件对比图的图例不能点击开关某条曲线。

## 2. 逐项对比

> 「我的判断」列是**无出处的结构性观察**，价值低于前两列，单独隔开。

### 2.1 频谱图（时频显示）

| | 内容 |
|---|---|
| 官方页说了什么 | RX：频谱图里可"可视化定位并替换不需要的声音"，可拖动选择区域做精细编辑；Audacity：频谱图支持 **Mel / Bark / ERB / Period** 四种刻度、三种算法（Frequencies / Reassignment / Pitch EAC）、窗型与零填充可调、可做时频选区；REW：提供 Fourier / Burst Decay / wavelet 三种频谱图 |
| audiocheck 实测 | 有频谱图（对数频域重采样 360 行 + `imshow`，一次重绘 **250 ms**；旧口径 `pcolormesh`+对数轴 442 ms），带 Bark 临界频带底纹 |
| **我的判断** | 差距在**刻度与交互**，不在"有没有这张图"：audiocheck 只有对数频率轴，没有 Mel/Bark/ERB 可选；没有缩放，没有选区。 Bark 底纹是抄了近路（底纹 ≠ 换刻度） |

### 2.2 频谱曲线（audiocheck 的主证据图）

| | 内容 |
|---|---|
| 官方页说了什么 | RX 有 Spectrum 分析仪模块，可显示播放头周围的瞬时频谱、所选时间/频率范围的平均频谱、或实时频谱；SPAN 是实时 FFT 分析器，支持立体声/单声道/Mid-Side 与 5.1/7.1，可显示二级频谱（实时最大 / 全时最大） |
| audiocheck 实测 | 单文件频谱曲线 + 1/3 倍频程平滑线叠放 + 噪底参考线 + 悬停读数（p95 20.1 ms） |
| **我的判断** | 这是**唯一一个 audiocheck 的图比它们更懂行的维度**：它画的是"这条曲线相对参考线/目标线在哪"，而 SPAN/RX 画的是"当前这一刻的谱"。 但 audiocheck 少了二级频谱/最大值保持这类**对照手段**，也没法把两条不同文件的谱并排叠（要跳到"多文件对比"页） |

### 2.3 缩放 / 平移 / 光标 / 标记

| | 内容 |
|---|---|
| 官方页说了什么 | Audacity：可在垂直（频率）轴缩放，右击刻度出菜单；REW：测量曲线可导出为文本、可对脉冲响应加倍频程滤波后显示、有完整的图形操作体系 |
| audiocheck 实测 | **无缩放、无平移、无标记**；只有频谱曲线的悬停 blit 读数 |
| **我的判断** | **这是最大的一处差距**，而且与"专业与否"的观感直接相关：一张不能放大的频谱图，读数只能"看个大概"，而"看个大概"恰恰是这类工具最不该有的状态 |

### 2.4 时频选区与编辑

| | 内容 |
|---|---|
| 官方页说了什么 | RX：Spectral Repair 用绘图工具选区并重合成，有多分辨率模式；Gain 模块可对选区做衰减/增强；Audacity：频谱选区 + 一组频谱编辑效果 |
| audiocheck 实测 | 无 |
| **我的判断** | **不该补**。audiocheck 的定位是"这个文件能不能拿去评器材"，不是修音频。 做了就是第二个 Audacity，而且永远做不到它那么好 |

### 2.5 批量

| | 内容 |
|---|---|
| 官方页说了什么 | RX：Standard / Advanced 均带 Batch Processor（批处理器） |
| audiocheck 实测 | 队列 + 多文件并行 + 表格增量刷新（单行 0.40 ms）+ 批次概览直方图/环形图 |
| **我的判断** | 这一项** audiocheck 不落后**：RX 的批处理是"对一批文件跑同一串处理"，audiocheck 的队列是"对一批文件出同一套判定并横向对比"，后者对它的目的更直接 |

### 2.6 报告 / 导出

| | 内容 |
|---|---|
| 官方页说了什么 | REW：频响可导入/导出文本、脉冲响应可导入 WAV/AIFF、可导出测量或滤波设置为 WAV；页面**未提**报告生成 |
| audiocheck 实测 | HTML / JSON / CSV / PNG 四种导出（`window.py:1103`） |
| **我的判断** | 有出处支持的不多，但四种格式 + HTML 报告对"交付给同事看"是够的。 差距在**图表不能单独导出为矢量**（PNG 是 160 dpi 位图） |

### 2.7 主题 / 可访问性

| | 内容 |
|---|---|
| 官方页说了什么 | 五个页面**都没有**提到对比度、色盲、深色模式或 WCAG 这类承诺（SPAN 只说"频谱颜色可自行选择"） |
| audiocheck 实测 | 配色由种子色算出，15 条 WCAG 判据在**生成时**强制执行（不达标抛异常）；装饰色阶另按非文本 3:1 判据；内置主题也照样过审 |
| **我的判断** | 这是 audiocheck **明确领先**的一维，但领先的是"工程纪律"而不是"功能"—— 用户看不见 15 条判据，只看见"字清楚不清楚"。 所以这一项要变成可感知的东西（种子色对话框里已经把对比度写出来了） |

### 2.8 键盘 / 效率

| | 内容 |
|---|---|
| 官方页说了什么 | Audacity 手册有专门的快捷键页；REW 有应用内帮助；两者都以菜单/工具栏为主 |
| audiocheck 实测 | Ctrl+K 命令面板（模糊匹配、键盘直达任意操作）+ 12 个快捷键 |
| **我的判断** | 命令面板是 audiocheck 的特色，方向正确；缺的是**快捷键自定义**与**图表内的键盘操作**（缩放/平移用键盘） |

### 2.9 通道 / 实时性

| | 内容 |
|---|---|
| 官方页说了什么 | SPAN：立体声/单声道/Mid-Side + 5.1/7.1；RX / Audacity：多轨 |
| audiocheck 实测 | 只有立体声/单声道相关的判定（相位相关、声道宽度、L/R 电平差、单声道兼容） |
| **我的判断** | 对"这个文件能不能用"这个问题，双声道信息已经够了；多通道与实时都是**别的工具的地盘**，追了会稀释定位 |

## 3. 差距清单（按该不该补分三类）

### A. 该补（用户价值高、成本可控）

| # | 差距 | 为什么值得补 | 难度（我的估计，无出处） |
|---|---|---|---|
| A1 | **频谱曲线/频谱图支持缩放与平移**（滚轮 + 拖拽 + 双击复位） | 最大差距；不能放大的图等于只能"看个大概" | 中：滚轮改 `set_xlim/set_ylim` 即可，但要和现有 blit 悬停共存（`charts.py` 的静态层快照要跟着失效） |
| A2 | **光标读数带十字线 + 频率/时间双轴读数** | 现在只有单轴；专业工具的基本功 | 小 |
| A3 | **图例可点击开关某条曲线**（多文件对比） | 10 条曲线叠在一张图上时，关掉几条是刚需 | 小 |
| A4 | **把判定结论钉到时间轴上**（选区 → 显示该区间的 LUFS/DR/削波） | 不需要编辑，只需要"指出是哪一段"；这是 audiocheck 独有的方向 | 中～大 |
| A5 | **bands / overview / waterfall 三张图过一遍精度自证** | `README` 已记的欠账：频谱图做过，其余三张没有 | 中 |

### B. 可选（做了更好）

快捷键自定义 ｜ 主题导入导出（分享种子色 + 档位）｜ 图表面板停靠 ｜ PNG 导出改矢量（SVG）

### C. 明确不追（与定位冲突，追了是负分）

| 方向 | 为什么不做 |
|---|---|
| 频谱编辑 / 修复 | RX 与 Audacity 的地盘；audiocheck 的职责是判定，不是修复 |
| 实时分析 | SPAN / friture / REW RTA 的地盘；audiocheck 面向离线文件审查 |
| 房间声学 / 扫瞄测量 / EQ | REW 的地盘，工具目的完全不同 |
| 多轨 / 环绕 | 判定"文件质量"不需要超过 2 声道的信息 |

## 4. 一句话结论

**差距集中在"图形的可交互性"（缩放/平移/光标/图例），不在"有没有这张图"。**
audiocheck 的图在**专业内容**上不落后（Bark 底纹、1/3 倍频程平滑、目标/参考线、
判定的效力边界），落后的是**让人看清细节的手段**。
另外两维它反而领先：可访问性（配色是算出来且有判据的）与
键盘效率（命令面板）——但这两维在官方页面上没有对应承诺，
所以严格说只能算"没有反证"，不能算"已赢"。
