# 测量原理与误差边界

本文说明每个数字**怎么来的**、**依据哪个标准**、**什么情况下不可信**。
一个不给误差边界的指标，比没有这个指标更糟——它会让人做出过度自信的判断。

---

## 1. 真实截止点（本项目最核心的判据）

### 1.1 为什么不能用"看频谱图"代替

人眼看频谱图只能判断"大约在哪"，而判定「44.1k 的 19.6k」与「48k 的 21.4k」需要
±0.2kHz 的稳定性。所以必须有确定性的算法。

### 1.2 算法（第五代，前四代都踩过坑）

```
1. 在**未平滑**的原始 Welch 谱上自高向低扫描
2. 在每个候选点 fc，比较两个窗口的中位数：
      下方 [fc/1.6, fc]  与  上方 [fc, min(fc*1.6, nyq)]
   若 下方 − 上方 ≥ min_drop_db（默认 15dB），认定此处存在陡降（**粗候选**）
3. 取阈值 =（通带中位数 + 阻带中位数）/ 2
   ⚠ 通带中位数取自**不跨骑候选**的窗 [fc/2.56, fc/1.6]（见 §1.6，v4.1 修）
4. 在原始谱上自高向低找第一个连续 3 点越过该阈值的位置，即为截止点
```

### 1.3 历代错法的成因（保留在此，防止退化）

| 版本 | 做法 | 错在哪 | 症状 |
| --- | --- | --- | --- |
| v1 | 按 1/12 倍频程步进下降，累计 N 步取当前频率 | 累计到 N 步时已越过边缘 N−1 步 | **恒定偏低**：44.1k 满带宽文件恒报 `22050/2^(2/12)=19.64k`，把满带宽 CD 误判成"轻微带限" |
| v2 | dB 域平滑 + 深阈值找边缘 | dB 域是算术平均，一半通带一半阻带会得到 `(0 + −90)/2 = −45dB`，边缘被抹成 12% 宽的过渡带 | **系统性偏高约 8%** |
| v3 | 功率域平滑 + "通带中位数 −3dB"的半功率点 | 用**全频段**中位数做参考；真实音乐的谱本身随频率向下倾斜，找到的是"谱穿过中位数的位置" | 一份实际延伸到 25kHz 的 96k 文件被判成 **6.8kHz** |
| v4 | 局部陡降 + 中点阈值（本文档 §1.2 步骤 1–2、4） | — | 合成基准误差 **−0.0%** |
| **v4.1** | v4 + **通带参考窗不跨骑候选**（§1.6） | v4 的通带参考窗 `[fc/1.6, fc]` 会跨骑候选；粗候选常落在真边缘上方 1.2–1.33× | **系统偏高**：96k 低截止 +25%、44.1k +10%（见 §1.6） |

### 1.4 两条必须遵守的实现细节

- **平滑必须在功率域**。dB 域的算术平均没有物理意义；功率域平均下，一半通带一半阻带恰好得到 −3dB（半功率点）。
- **扫描必须用原始谱**。功率域平滑窗口为 ±1/6 倍频程（≈±12%），当截止点距奈奎斯特很近时（如 44.1k 容器、内容到 19.5k），平滑后上方只掉 8.6dB，判定器完全看不见。

### 1.5 误差与不可测区间

| 情形 | 表现 |
| --- | --- |
| 陡降明显（有损/升频） | 相对误差 **≤1.3%**（v4.1 起；v4 时最低到 96k 的 +25%，见 §1.6） |
| 边缘距奈奎斯特 <10% | 分辨率下降，可能报成"直达奈奎斯特"；已用"顶部 5% 频段落差"兜底，但极端情况仍会漏判 |
| 自然滚降（如 2 阶巴特沃斯） | 正确判为"无截止"（阻带不够深，<20dB） |
| 数字静音 | 直接返回"无内容"，不猜 |

### 1.6 v4.1 精度修正：通带参考窗**不能跨骑候选**（2026-10-17）

**发现方式**：E1 属性测试只敢覆盖 ≥12 kHz、容差松到 15%（当时登记"9–12 kHz 精度判据未立"）。
本轮把误差**曲面**量出来（入库探针 `packaging/cutoff_calib.py`，密集网格 × 三采样率），
看到 96k 低截止处系统性偏高：**+25%（6 kHz）、+15.6%（8 kHz）、+14.7%（9 kHz）**。

**机制**（打中间量证实，不是猜）：粗候选来自 1/12 倍频程步进，
常落在真边缘上方 **1.2–1.33×**。此时 v4 用来算阈值的通带参考窗 `[fc/1.6, fc]`
**跨骑**了边缘 ⇒ 窗内通带占比 <50% ⇒ **中位数落到阻带底** ⇒ `thr=(通带+阻带)/2`
塌陷到数值噪声底 ⇒ 第 4 步命中的是"噪声底越过该电平"的位置，**系统性偏高**。

**修法**：通带参考窗改为**带间隙、不跨骑**的 `[fc/2.56, fc/1.6]`（因候选 <1.6× 真边缘，
此窗必在通带内）；**粗搜索与守卫窗一字未改** ⇒ **"是否判为带限"的集合不变**
（`cutoff=None` vs 有值 的决定不动），只有带限文件的截止点**读数**变准。

⚠ **读数变化会传导到判定等级**：判定把 `cutoff_hz` 与 `hi_ok`/`ltd`/`lossy` 等门限比较，
读数下移会让**跨门限的文件改档**（不是"只动值不动判"——那是草率结论，已更正）。
同一份真实曲库只换 cutoff 实现对照跑（448 文件）实测：**等级翻转 55/448**、
`ok 82→78`/`warn 226→227`/`bad 140→143`；截止点中位变化 0.12 kHz、最大 11.35 kHz。
方向是**修正**：旧值把 96k 内容截止点报得虚高 ⇒ 误判"真 Hi-Res"。
（复算器：`packaging/cutoff_impact.py`，`--make-old` 可把旧实现覆盖进当前模块以隔离变量。）

**实测（250 Hz 步长扫 [6000,21000] × {44.1k,48k,96k}，`packaging/cutoff_calib.py`）**：

| 指标 | v4 | v4.1 |
| --- | --- | --- |
| 最大相对偏差 | **25.0%**（96k @ 6 kHz，44.1k 10.0%） | **1.27%**（96k @ 6 kHz） |
| 最大跨采样率散布 | 10.2% | **0.69%** |
| 满带宽 / 自然滚降 / E1 回归点（合成） | 不变 | **不变**（逐点核对） |
| 真实曲库判定等级 | — | **55/448 改档**（更准）；全量 450 文件 = ok 78 ｜ warn 229 ｜ bad 143 |

属性测试据此从「≥12 kHz、15%」收紧到「**[6,21] kHz、3%**」（`tests/test_props.py`）。

## 2. 响度：ITU-R BS.1770-4

### 2.1 K 加权

两级 biquad，系数按**实际采样率实时重算**（不是照抄 48kHz 表）：

**第一级：高架滤波**（补偿人头对高频的增益）
```
f0 = 1681.974450955533 Hz,  G = +3.999843853973347 dB,  Q = 0.7071752369554196
K  = tan(π·f0/fs),  Vh = 10^(G/20),  Vb = Vh^0.4996667741545416
b = [(Vh + Vb·K/Q + K²)/a0,  2(K² − Vh)/a0,  (Vh − Vb·K/Q + K²)/a0]
a = [1,  2(K² − 1)/a0,  (1 − K/Q + K²)/a0],   a0 = 1 + K/Q + K²
```
**第二级：高通**（去除次声与直流）
```
f0 = 38.13547087602444 Hz,  Q = 0.5003270373238773
b = [1, −2, 1],  a = [1, 2(K²−1)/a0, (1 − K/Q + K²)/a0]
```

### 2.2 门限积分

```
块长 400ms，步进 100ms（= 4 个 100ms 步，用卷积做滑窗，矢量化）
逐块均方 z_j = Σ_channels mean(y²)
块响度 l_j = −0.691 + 10·log₁₀(z_j)

绝对门限：保留 l_j > −70 LUFS
相对门限：阈值 = (绝对门限内均值对应的响度) − 10 LU，再筛一次
积分响度 = −0.691 + 10·log₁₀( Σz_gated / N_gated )
```

**为什么必须门限**：不门限的话，一段长静音会把整轨响度拖低好几 LU，
不同曲目的读数就不可比了。这是 BS.1770 与"简单 RMS"的本质区别。

### 2.3 验证方式

测试用"同一正弦、幅度减半"，断言响度下降 **6.02 LU**。
这比断言绝对值稳——它验证的是**标度不变性**，不依赖具体实现细节。

## 3. 响度范围 LRA：EBU R128 Tech 3342

在 K 加权信号上取**短时块 3s / 步进 1s**，同样做 −70 LUFS 绝对门限
与 −20 LU 相对门限，然后：

```
LRA = P95(短时响度) − P10(短时响度)
```

取 P95/P10 而非 max/min，是为了排除个别极值段的干扰。

> **DR 与 LRA 的区别**：DR（动态范围）是行业惯用的近似指标，本项目给出的
> `dr_db = 采样峰值 − 最响 20% 块的均方根`，**明确是近似 TT-DR，不宣称等同
> 官方 DR Meter 输出**（官方算法未完整公开）。真正标准化、可复现的动态量是
> **LRA**。判断"能不能用来评耳机动态"时应看 LRA。

## 4. 真峰值：ITU-R BS.1770-4 Annex 2

采样点不超 0 dBFS，不代表**重建后的模拟波形**不超。
在 DAC 的插值重建中，相邻采样点之间可能过冲。

```
对每个声道做 4 倍过采样（多相 FIR 重采样），取过采样序列的峰值
true_peak_dbfs = 20·log₁₀(max|x_oversampled|)
```

**实现细节**：分段重采样时丢弃每段首尾各 10%，避免滤波器边界瞬态造成的虚假峰值。

**为什么重要**：真峰值 > 0 dBTP 意味着在真实 DAC 上会削顶——
这是"母带做过了"的确凿证据，且**不该算到耳机头上**。

## 6. 位深升位检测（**可作证据**）

### 6.1 原理

把 16bit 内容装进 24bit 容器，有两种写法：
- **补零**（常见）：`stored24 = v16 << 8` → 存储值低 8 位恒为零
- 直接写入：`stored24 = v16` → 这只是"电平低"，**不是升位**

### 6.2 实现要点（踩过的坑）

libsndfile 把整数 PCM 读成 `int32` 时会**左移对齐**：24bit 内容读到的是 `stored24 << 8`。
所以"低位全零"里有一部分是**格式固有**的，必须先扣除：

```
inherent = 32 − 标称位深        # 24bit → 8
low      = 所有样本按位或后的最低置位
extra    = low − inherent       # 这才是真正的填充位数
若 extra > 0 → 实为 (标称位深 − extra) bit
```

**为什么不能用电平判断**：安静的 24bit 素材本来就用不满位数，
按"有效量化级数"反推会把它误判成升位。**电平和位深是两回事**。

## 7. 频谱估计：Welch 法与它的边界

```
分段：取 25% / 50% / 75% 三处各 20 秒，做 Welch 平均后相加
参数：nperseg = 16384，50% 重叠，Hann 窗
```

- **频率分辨率** = `fs / nperseg`：44.1kHz 下约 **2.7 Hz**；
- **平滑段数** ≈ 20 段 → 单点估计的标准差约 ±1.2dB；
- 这解释了为什么截止点检测要在**原始谱**上找陡降，而不是在单点上比大小。

**可测下限**：频率下限受窗口长度限制，本项目取 20Hz 作为有效下界
（`f[0]=0` 是直流分量，**不能**作为循环下界——这是 v1 死循环事故的根因）。

## 9. 汇总：哪些数字能当证据

| 指标 | 可作证据？ | 理由 |
| --- | --- | --- |
| 真实截止点 | ✅（陡降明显时） | 确定性算法，误差 <1% |
| 真峰值 | ✅ | 标准定义，4 倍过采样 |
| 集成响度 / LRA | ✅ | 标准定义，门限逻辑完整 |
| 位深升位 | ✅ | 位级判据，与电平无关 |
| 削波样本比例 | ✅ | 直接计数 |
| 编码器类型 | ⚠️ 线索 | 典型值，非唯一解 |
| DR | ⚠️ 近似 | 官方算法未公开 |
| 频段能量占比 | ⚠️ 参考 | 依赖 Welch 参数与取样位置 |
| 谱低端百分位 | ⚠️ 参考 | **不是噪声底**——它是频谱第 5 百分位，不代表静音段的本底 |

### 9.1 本表是**权威**：UI 不许展示表里没有的数字

C0-5 立的规矩。两条：

1. **界面上出现的每一个数，都必须能在这张表里找到它（以及它的可信度）。**
   找不到就不许显示——"看起来是个测量值"和"真的是个测量值"必须一致。
   反面例子（已修）：`noise_floor_db` 实际是**频谱第 5 百分位**，却在指标卡与
   图表参考线上都叫"**噪声底**"。叫噪声底会让人以为它来自静音段测量，
   而"静音段"在本项目里**没有判据**（要立判据就得先定"多静算静音"这个新阈值，
   属 C1 的范围）。现在按实际含义命名：**谱低端百分位**。
   （数据键仍叫 `noise_floor_db`，为 JSON 兼容；界面文案不许再写"噪声底"。）

2. **表里的可信度等级要跟着数字走。**标 ⚠️ 的指标在报告/导出里不许
   以确定语气出现（"DR 为 8.2" 要写成 "DR ≈ 8.2（近似）"）。

### 9.2 C4 立的三条输出规矩（用户 2026-10-13："极致真实丰富"）

1. **三层分开，不许压平**：现象层（`phenomena`）／成因层（`causes`）／用途层
   （`usability`）各自成结构。成因候选**并列输出**并标"无法区分"，不许压成
   一个结论；用途矩阵不许压成分数；判定行不许用"｜"糊成一行。
2. **证据不足不硬判**（C4.6）：砖墙陡度不足（conf < `conf_low`）时，带限类
   判定只能 `warn` 不能 `bad`——"有损溯源"是对**成因**的硬断言，需要陡砖墙
   作证据。等级（level）与成因（causes）分开：level 答"有不有问题"，
   causes 答"像什么原因"。
3. **"未知"是正式取值**：缺数据 ⇒ "不可判"（用途矩阵）／"无法统计"（位深），
   不许默认成"没问题"。每次运行印一次 `boundaries`（效力边界）。

## 10. 假 Hi-Res 盲检测（C3）：一个**负结论**的方法节

方法链来自 NYCU 2017 学位论文（席冠文、羅濟群；**学位论文、未独立复现**，
引用它不等于采信它的 98%）：
**取差分 → 取绝对值 → 取对数 → FFT → 对数等距 6 段取均值作特征 → 分类**。
本项目用自实现逻辑回归（不引运行时依赖；SVM→LR 是为系数可读可复算）。

**自建验证集的实测结论（可复算：`python packaging/fakehires_eval.py`）**：

| 集 | 内容 | 结果 |
|---|---|---|
| 训练 | 粉噪/白噪 ×（原生 / 升频 / 有损后升频） | 准确率 0.875 |
| 测试 | 没见过的"类音乐"内容 | **误报率 0.722** |

**归因（拆开看的）**：L2 归一后的 6 段特征是**整体谱形描述**，被内容滚降
主导——噪声源上"假"样本顶部带塌掉、差异大；谱形自然滚降的内容上差异小。
真正把两类分开的是"22 kHz 以上有没有真实能量"，而**那一项本项目已经有
`cutoff_hz` 在测、且更可靠**。

⇒ **判定：该特征不构成截止点之外的增量，且跨内容类型不泛化。**
输出一个测试集误报率 72% 的分类器比没有它更糟（用户会去信）⇒ 分析器
**默认关闭**（`enabled = False`，判定写进源码 docstring），代码与验证脚本
保留。重开：`--only fakehires`。升格为判据的前提：**真实曲库**上误报可接受
（未做）。调参过程中的三次失败（训练集 recall=0 ⇒ 类不平衡；测试集误报
0.806 ⇒ 语料"类音乐"名不副实）记在 `tests/test_c3_fakehires.py` 与 CHANGELOG。

## 11. 判定层理论：三层输出的认识论（C4，2026-10-16 落纸）

用户原话："判决颗粒度一定要根据现实音源复杂情况极致真实丰富。"
本节回答**为什么必须是三层**，以及每层的推理规矩从哪来。

### 11.1 三层的认识论定位

| 层 | 输出 | 推理类型 | 规矩 |
|---|---|---|---|
| 现象层 | 测量值 + 等级 | **测量**（确定性） | 每个数有出处或标"工程估计"；区分力可查 |
| 成因层 | 候选集 + 证据/反证/强度 | **溯因推理**（abduction） | 并列候选、不许硬判一个；无出处标"疑似" |
| 用途层 | 每格 可用/受限/不可用/不可判 | **测量效度映射** | 每格带依据；判不了的写"不可判" |

三层的错误是不同的东西，混在一层就全都失真：把"像什么原因"（溯因，天然
不确定）压进"有不有问题"（测量，要求确定），等级就不再表达任何明确的
东西——这是 C4 之前的病；把"能拿它评什么"（效度）塞进成因，用户会以为
结论在说文件而不说用途。

### 11.2 溯因推理的规矩（皮尔斯框架的项目化）

1. **候选 ≠ 结论**。现象支持多个相容假设时，输出**全部候选** + 各自证据；
   "无法区分"是**正式状态**（`ambiguous` 标记），不是失败。
   实例：黑胶 vs 磁带——区分证据是 wow/flutter（抖动）与爆音，**本项目
   测不了**，所以两者永远并列出现，直到有判据。
2. **反证与证据对称**。候选带 `counter[]`：硬砖墙是黑胶的反证（更像转档）。
   只有支持证据没有反证检查的候选，是在做确认偏误。
3. **强度（strength）的统计定义**：砖墙类候选的 strength 就是带宽轴的
   `conf`——砖墙陡度在证据区间 [8, 24] dB/oct 上的**归一化位置**。
   ⚠ 它**不是概率**（p(有损｜谱) 需要先验，我们没有），不许在文案里写成
   "概率"或"置信度 %"。非 conf 派生的粗档（0.5/0.8/0.9）是**证据类型的
   工程分级**（统计吻合/容器级失配/位级），同样不是概率。
4. **出处分级 ↔ 判据强度**：位级判据（位深填充）可作硬证据；有学术出处
   （升频，NYCU 2017）可作线索级；工程估计一律"疑似"。**无出处不许当
   证据用**——C2 出处账与 §9 表是这个映射的账本。

### 11.4 用途矩阵的理论：测量效度

"能拿它评什么" = **测量效度**问题：一个指标能不能回答某个问题，取决于
问题的信息是否存在于测量里。三条推导规矩：

1. **信息在源头就没了 ⇒ 不可用**（内容止于 16kHz 评不了高频延伸）；
2. **问题被别的失真掩盖 ⇒ 受限**（削波掩盖细节、响度战掩盖动态）；
3. **测量原理上不覆盖 ⇒ 不可判**（结像需要双耳数据——**不是"没问题"，
   是"问错了工具"**；瞬态受 93ms 分析窗限制）。

这就是"未知是正式取值"的效度版本：`不可判` 与 `可用` 一样是**有信息的
结论**，压平成"没问题"才是失真。
