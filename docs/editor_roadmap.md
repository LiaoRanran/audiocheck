# 从"体检"到"编辑"：audiocheck 专业化路线（2026-10-18 记）

> 本文是**范围变更的记账**，不是偷偷改口径。
> 旧口径（已入库）：`docs/ui_compare.md:158`「频谱编辑 / 修复｜RX 与 Audacity 的地盘；
> **audiocheck 的职责是判定，不是修复**」；`CHANGELOG.md:1236`「**频谱编辑、实时分析、
> 房间声学三项明确不追**」。
> 新口径（用户 2026-10-18 决定）：**往专业音源编辑制作的开源软件靠，填 Windows 市场**；

## 1. 市场事实（诚实版，别自我打气）

| 工具 | 平台 | 授权 | 与本项的关系 |
|---|---|---|---|
| iZotope RX | Win+Mac | 商业（贵） | **频谱修复标杆**，流程黑盒 |
| Steinberg SpectraLayers | Win+Mac | 商业 | **频谱编辑标杆**（图层/选区） |
| Acon Digital Acoustica | Win+Mac | 商业 | 修复 + 批处理 |
| Adobe Audition | Win+Mac | 订阅 | 全功能，重 |
| Audacity | 跨平台 | GPL | **开源但修复弱、工程薄** |
| ocenaudio | 跨平台 | 免费闭源 | 轻量 |
| REAPER | Win 优先 | $60 | DAW，非修复专精 |
| Sonic Visualiser | 跨平台 | GPL | 分析，**不编辑** |

**结论**：Windows 原生 + 开源 + **专业级频谱编辑/修复**目前**没有强玩家** ⇒ 缺口真实存在。
**但必须诚实**：开源**不是卖点**，能力才是——用户不会因为开源换工具。所以定位不能是
"再做一个能刷频谱图的编辑器"，那没有赢面。

## 2. 我们真正不同的资产（不是"有频谱图"）

现有内核是**可复算、带出处、带效力边界**的测量系统：**753 用例**、9 个 `--strict` 探针、
变异分数 **102/102 = 1.000**、每个阈值有出处账（`docs/thresholds.md`）、每个结论有边界（`causes.boundaries()`）。

⇒ **差异化定位：可审计的修复（auditable repair）。**
竞品是"黑盒修复"——点了"De-noise"你不知道它改了什么。本项目可以把**每一次修复**都给出：
**改了什么 / 为什么 / 依据哪一条测量 / 置信度 / 可复算**。这正好接住已有的全部纪律，
且是别人**没有**的东西。**这条是路线的锚**，其余功能围绕它建。

## 3. 现状盘点（别高估）

**已有**：分析引擎、频谱/相位/瀑布/时间轴视图、频率刻度（Bark/Mel/ERB/线性）、配色系统、
无障碍、命令面板、帮助面板、判定与成因候选。
**没有（全部要新建）**：音频**播放**引擎、**编辑文档模型**、**选区模型**、**撤销/重做**、
**渲染/导出**、**格式写入**（现在只有 `timeline.py` 里一处临时 wav）。
⇒ 编辑器的四根柱子（I/O、播放、编辑模型、渲染）**目前一根都没有**。

## 4. 路线（P0→P5；每级必须"可用 + 可验证"）

| 级 | 内容 | 出口判据（可测） |
|---|---|---|
| **P0 地基** | `core/edit/`：非破坏**文档模型**（操作栈）+ **渲染引擎**（float32；重采样 soxr；抖动；写 WAV/FLAC/AIFF） | **往返测试**：读→改→写→读，未选中处**逐位不变**、选中处与预期差值在容差内 |
| **P1 播放** | 低延迟播放引擎（miniaudio/PortAudio），与视图联动（播放头/跟播） | 起播延迟、X-run 计数、设备切换不崩 |
| **P2 选区与增益** | 时间×频率**选区**（矩形→套索）；**增益**（选区衰减/增强）——最简且最有用 | 选区=矩形时与"直接对该段做增益"**逐位一致**；撤销栈正确 |
| **P3 修复算法（自研，逐个带判据）** | declip / declick / decrackle / dehum / denoise（多分辨率谱减）/ 去削波 | 每个都要先建**合成缺陷语料 + 客观指标**（SNR 提升、伪影谱），再过真素材 |
| **P4 工作流** | 批处理、宏、A/B、导出预设、动作日志导出（→"可审计"落地） | 批处理可复算；A/B 无副作用 |
| **P5 生态** | VST3/CLAP 插件、脚本、工程格式、i18n/无障碍收口 | 插件在宿主里与内核**同一结果**（互证） |

**顺序理由**：P0 是**所有**后续的地基，且**立刻可验证**；P3 的算法难度最高，放到地基与
播放稳了之后——否则会重演"先做花哨功能、判据没立"的老坑。

## 5. "极致与专业"的可测定义（不许含糊）

沿用既有纪律，给编辑部也立同类判据：
1. **无损往返**：未被编辑的采样**逐位不变**（非破坏 + 精确撤销）。
2. **测量互证**：修复后再用**同一个测量内核**量一次，证明确实只改了目标（如 dehum 后
   50/100 Hz 峰下降、其余频段差异 < 阈值）。
3. **客观指标**：每个算法有合成语料上的 SNR/SDR 提升与伪影下限，且**效果边界**写进 UI。
4. **性能**：选区操作在 X 秒素材上 ≤ Y 秒（沿用 `perf_probe` 的口径与阈值表）。
5. **可审计**：每次操作产出机器可读记录（算法/参数/依据/时间），可复算。

## 6. 非目标（明确不做，免得摊大饼）

- **不做通用 DAW**（多轨混音、MIDI、虚拟乐器、总线）。
- **不做实时处理宿主**。
- **不追全格式**：先 WAV/FLAC/AIFF；MP3/AAC 走 **ffmpeg 只读**→编辑后导出的路径。
- **不改判定内核的既有职责**：编辑器**读**测量结果，测量层**不** import 显示/编辑层（既有纪律）。

## 7. 风险（诚实，别只看好处）

- **工程量**：编辑 + 播放 + 渲染 ≈ 当前分析内核的**数十倍**；不可能一轮到位。
- **播放是独立难题**（低延迟、设备热插拔、ASIO/WASAPI 差异）。
- **听感判据难**：频谱修复的"好不好听"必须建**主客观双层评测**，否则会重演
  "假 Hi-Res 分类器"的教训（外部有效性不足就升格）。
- **许可证**：本仓已有 SBOM 纪律 ⇒ 新依赖（ffmpeg / soxr / miniaudio / VST3 SDK）的许可
  要**逐条核**并入账；GPL 传染性会影响整体授权选择。

## 8. 第一步（最小可验证增量，建议直接开工）

**不先碰 UI**，先做 **P0 的地基切片**：
一个 `core/edit/` 的**非破坏增益渲染**——读文件 → 对**时间选区**加 −X dB → 写文件，
带两条判据：
1. **往返测试**：选区外**逐位不变**（用真实曲库文件，不只合成）。
2. **与测量内核互证**：改完用现有引擎再量一次，证明**只有选中时段变**、电平差值 == X dB（容差内）。

**为什么是它**：把四根柱子里的 **I/O + 渲染**两根先立起来，**立刻可验证**、不依赖播放与 UI，
且天然产出"可审计修复"的第一条记录。

**状态**：✅ **已完成**（`core/edit/ops.py`、`render.py`、`edit_cli.py`；
判据 13 条在 `tests/test_edit_render.py`、8 条在 `tests/test_edit_cli.py`）。

### 第二步：**频域通路**（时频选区增益）—— ✅ 已完成（2026-10-18）

### 第三步（**已收口**）：**先建指标、再决定要不要上软掩码** —— ✅ 2026-10-18

**先建了指标**：`core/edit/metrics.py`（带内衰减实测 / 脉冲包络宽度 / SDR / 能量比——四个
都只出数、不出"好/坏"），并把"**设定 vs 实测**"写进审计与 CLI（可审计的修复）。
**再用指标做了决策实验**（`packaging/mask_tradeoff.py`，4 种掩码 × 2 种写回 × 4 列）：
谱底 −40 dB 花 20 dB 压制度买不到东西；50 ms 时间锥形花 50 ms 选区精度只换 1.6 倍包络改善；
真正需要的东西（**外扩跨度**）我们已经有了。
⇒ **结论：软掩码不进内核**（`docs/editor_research.md §7`、`docs/theory.md §12.7 ⑤`）。
⚠ 这一项在编辑升级到"**挖点/补点**"（时频修音 / declip / declick）时要**重开**。

### 第四步（**已完成**）：**P3 修复算法的判据骨架 + 第一个修复算子** —— ✅ 2026-10-18

**先建判据再写算法**（`docs/editor_research.md §8` 记全过程）：
1. `core/edit/corpus.py` —— **有真值的合成语料**：带宽已知的干净信号（`harmonic_tone` /
   `band_limited_noise`）、**硬削波三档**（`CLIP_TIERS`，severe 档饱和占比实测 22.7%，
   把 Záviška "既有基准太软"那条教训钉成语料判据）、脉冲位置已知的 `click_train`。
2. `packaging/declip_probe.py` —— **先量四种候选重建**（插值 / 样条 / Papoulis–Gerchberg /
   POCS），同一把尺子（`sdr_db` + `energy_ratio_db`）。
3. `core/edit/declip.py` + `ops.DeclipOp` + render 的 declip 路径 + CLI `--declip`：

**这一轮的关键结果是负面的**：局部插值（工程界 Audacity ClipFix 那一族）**把 SDR 修坏**

密集削波只 +4 dB 量级）全部写进审计与 CLI。判据 **46 条**在

编辑侧四个模块变异**逐模块 1.000**（记账见 `CHANGELOG.md` 本轮的"探针维护"一节）。

### 第五步（**① 已收口 / ② 仍挂账**）：**`B` 的来源 + 密集削波那一族** —— 2026-10-19 更新

**① `B` 的来源（✅ 本轮收口）**：测量层新增 `spectrum.content_bandwidth`（**单一出口**；
编辑层仍不 import 测量层，由 CLI 在边界层接起来）。口径**实测定的**
（`docs/editor_research.md §9`、`docs/theory.md §12.9`）：
**有砖墙截止就用它；量不到 ⇒ 奈奎斯特 ⇒ 去削波如实退化成逐位不变**。
**不许**拿能量滚降点当 `B`（那是 *spectral rolloff point*——能量分布的统计量、不是边缘估计；
实测偏低 4.9%–17.5%、端到端把 SDR **修坏 −1.5 dB**）。CLI `--bandwidth` 省略即自动，
审计记 `bandwidth_source ∈ {given, auto_cutoff, auto_nyquist}`。
边界也已量掉：**severe 档证据被削波谐波填掉** ⇒ 自动读数失效；**素材 < ~0.91 s**
量不出 canonical 谱 ⇒ **明确拒绝**（不猜一个 `B`）。

**② 密集削波（机制已量清 ／ 修法仍挂账）**：第五轮把"severe 卡住"的**机制**量出来了
（`docs/editor_research.md §10`、`docs/theory.md §12.10`）：**不是迭代不够，是解集不唯一**——
判据 `f > 1 − B/(fs/2)`（时间-带宽自由度计数，Landau–Pollak 1962），并已落地为
**可辨识性预判**（审计 + CLI 的 `ambiguity_margin / ambiguous`）。
**稀疏那一族本轮实测不足以落地**（只在"稀疏素材 + 轻削波"胜出 +6.1 dB；带限白噪上全面不如 POCS，
且更慢更复杂）⇒ 若下一轮继续：先换**严格实现**的稀疏/相位感知求解器（SPADE 谱系 / PHAIN），
**在稀疏素材上**建判据；且**欠定侧的目标不是"逼近真值"**（做不到），而是**给一致解 + 明说局限**。
另：**低截止素材**（截止点 < `cutoff_min_hz`）上 `detect_cutoff` 按既有口径**拒绝给读数**
⇒ 自动 `B` 偏保守（退化为奈奎斯特）；本轮**未量**"拿真实低截止当 `B` 能修回多少"，留作下一轮。

### 第六步（**已完成**）：**P3 第二个修复算子：去咔哒** —— ✅ 2026-10-20

`corpus.click_train` 早两轮就备好了**位置已知**的咔哒 ⇒ 这一轮同样是**判据先行**
（`packaging/declick_probe.py`，四种素材 × 六档阈值），量出来两条**否决**与一条**非对称代价**：

* **残差口径**：邻域中值残差**被否决**（平滑素材上 α 扫到 12 仍有 15% 假阳性）
  ⇒ 用**两点预测残差**（平滑内容上残差 ≈ `(2πf/fs)²·|y|`，比咔哒小两个数量级）；
* **尺子**：**局部**滑动尺子**被否决**（同一误报率下 SDR 更差）⇒ 用**全段 MAD**；
* **阈值 `α = 5.0`**：**代价不对称**——误报到 ~1e-3 就把信号**修坏**（白噪 −9.96 dB），
  而 TPR 掉一点只让收益从 +14.2 变 +3.6 ⇒ 规则 = "**先压误报、再看收益**"。

落地 `core/edit/declick.py` + `DeclickOp` + render 的 declick 路径 + CLI `--declick`：
**只改检出样本**（选区外逐位不变、选区内未检出样本逐位不变），审计报
`threshold / detected_samples / fraction / residual_scale / changed_samples / 能量比`，
改动面 > 0.5% 时**主动警告**。效力边界如实写：**收益由素材的可预测性决定**
（平滑 +40.6 / 瞬态 +6.5 / 谐波音 +3.6 / **带限白噪只 +2.0**）。
判据 **14 条**在 `tests/test_edit_declick.py`（+ CLI 侧 2 条）。

### 第七步（**① 已收口 / ②③ 仍挂账**）：**把"检测"这一级做强 + 还历史债** —— 2026-10-21 更新

### 第八步（**已收口**）：**P3 第三个修复算子：去嗡** —— ✅ 2026-10-22

同样是**判据先行**（`packaging/dehum_probe.py`：3 族候选 × 2 素材 × 2 基频 × 2 电平，外加
频率漂移扫描）。三条实测结论（`docs/editor_research.md §13`、`docs/theory.md §12.13`）：

* **STFT 置零否决**：谐波音上最好（46.9 dB），带限白噪上崩到 21.0（零相位 26.8）——
  置零 ±24 Hz 等于挖掉 4 个 bin 的**内容**，与 §7 "软掩码不进内核"同型；
* **零相位赢因果**（同 Q 高 2–3.6 dB）：离线修复没有理由付相位失真；
* **Q=10 由漂移定**：Q 决定陷波宽 `f0/Q`；嗡漂 1 Hz 且按标称值设计时，Q=10 仍压 17 dB，
  Q=40 只剩 2.9 dB（≈ 没去）。**默认值取"对输入误差鲁棒"的那个**。

落地 `core/edit/dehum.py` + `DehumOp` + render 的 dehum 路径 + CLI `--dehum/--hum-f0`；
审计报 `harmonics_used / skipped_harmonics / suppression_db（实测）/ changed_samples`。
**效力边界如实写**：陷波是 **LTI ⇒ 整段选区都被改动**（干净素材上 Q=10 的改动量
= SDR 27.6 dB、能量 −0.017 dB）⇒ 收益由嗡的能量占比决定。
判据 **12 条**在 `tests/test_edit_dehum.py` + CLI 侧 5 条。
**挂账**：f0 自动检测（需先立"嗡线 vs 音乐基频"的判据）、非稳态嗡（漂移/抖动）、
与其它修复算子的叠加顺序。

### 第九步（**已收口**）：**去嗡的 `f0` 自动检测** —— ✅ 2026-10-23

上一轮留的第一条挂账在这一轮用**判据先行**解决
（`packaging/hum_detect_probe.py`、`docs/editor_research.md §14`、`docs/theory.md §12.14`）：

* **谐波族不是判据**：实测 55 Hz 衰减贝斯的 excess **34.7 dB**，比 −30 dB 的嗡还高；
* **稳态才是**：帧间稳定（嗡 ≤11.3 / 乐音 ≥495 dB）+ 安静帧仍在（嗡 ≥3.2 / 乐音 ≤−3.4）；
  三个门限（4 / 30 / 0 dB）都落在**实测空隙**里；`0 dB` 取的是自然边界；
* **亚 bin 插值**：2.93 Hz 格点下不插值会把 60 Hz 报成 61；三 bin 抛物线后 50.02 / 60.04；
  窗长随采样率缩放 ⇒ 频率格恒定。

落地 `core/analyzers/hum.py`（`detect_hum`）+ CLI `--hum-auto`（与 `--hum-f0` 互斥）+
`DehumOp.f0_source ∈ {given, auto}` 进审计。**证据不足就拒绝**（退出码 2、打印三项实测）。
判据 **30 条**在 `tests/test_analyzer_hum.py`（8 条端到端 + 22 条**打桩谱图**：
窗口端点 / 分位 / 抛物线插值 / 窗长缩放 / 边界守卫）+ CLI 侧 3 条；
**变异复跑 76/76 = 1.000**（等价 4 条，理由已登记）。
**边界**：稳态低音持续音与嗡不可区分 ⇒ 自动路径只"发现并报证据"，动手仍由用户决定。
**仍未做**：非稳态嗡（漂移/抖动）、修复算子的叠加顺序。

### 第十步（**已收口**）：**P0 往返测试的格式覆盖 + 子类型守卫** —— ✅ 2026-10-24

P0 的出口判据（"读→改→写→读，未选中处逐位不变"）此前**只在 WAV 上验过**。
本轮把 **FLAC / AIFF × PCM_16 / PCM_24 / FLOAT** 补上（`tests/test_edit_formats.py`，14 条）：

* 七种组合全部：选区之外**逐位不变**、选区内实测 **−6.000 dB**（容差 0.02）、子类型原样保留；
* **0 dB（恒等）渲染整文件逐位不变**（三次量化不引入漂移）；
* 渲染前后**源文件 sha256 不变**（非破坏的硬保证）；
* 修复算子 × 格式：去嗡在 FLAC 上同样"选区之外逐位不变"。

**顺带修掉一个真问题**：源是 `FLOAT`（WAV）、目标是 `.flac` 且没显式给 subtype 时，
原来会继承 `FLOAT` ⇒ libsndfile 在**目标文件已经建了一半**之后才抛
`Invalid combination of format, subtype and endian`。现在 `render._check_subtype`
用 `sf.check_format` **在动目标之前**拒绝，信息里直接给修法（`subtype="PCM_24"`），
并保证**拒绝路径不留下半个目标文件**（判据里断言了这一点）。
