# 从"体检"到"编辑"：audiocheck 专业化路线（2026-10-18 记）

## 1. 市场事实（诚实版，别自我打气）

| 工具 | 平台 | 授权 | 与本项的关系 |
|---|---|---|---|
| iZotope RX | Win+Mac | 商业（贵） | **频谱修复标杆**，流程黑盒 |
| Steinberg SpectraLayers | Win+Mac | 商业 | **频谱编辑标杆**（图层/选区） |
| Acon Digital Acoustica | Win+Mac | 商业 | 修复 + 批处理 |
| Adobe Audition | Win+Mac | 订阅 | 全功能，重 |
| Audacity | 跨平台 | GPL | **开源但修复弱、工程薄** |
| ocenaudio | 跨平台 | 免费闭源 | 轻量 |
| REAPER | Win 优先 | $60 | DAW，非修复专精 |
| Sonic Visualiser | 跨平台 | GPL | 分析，**不编辑** |

**结论**：Windows 原生 + 开源 + **专业级频谱编辑/修复**目前**没有强玩家** ⇒ 缺口真实存在。
**但必须诚实**：开源**不是卖点**，能力才是——用户不会因为开源换工具。所以定位不能是
"再做一个能刷频谱图的编辑器"，那没有赢面。

## 2. 我们真正不同的资产（不是"有频谱图"）

现有内核是**可复算、带出处、带效力边界**的测量系统：**753 用例**、9 个 `--strict` 探针、
变异分数 **102/102 = 1.000**、每个阈值有出处账（`docs/thresholds.md`）、每个结论有边界（`causes.boundaries()`）。

⇒ **差异化定位：可审计的修复（auditable repair）。**
竞品是"黑盒修复"——点了"De-noise"你不知道它改了什么。本项目可以把**每一次修复**都给出：
**改了什么 / 为什么 / 依据哪一条测量 / 置信度 / 可复算**。这正好接住已有的全部纪律，
且是别人**没有**的东西。**这条是路线的锚**，其余功能围绕它建。

## 3. 现状盘点（别高估）

**已有**：分析引擎、频谱/相位/瀑布/时间轴视图、频率刻度（Bark/Mel/ERB/线性）、配色系统、
无障碍、命令面板、帮助面板、判定与成因候选。
**没有（全部要新建）**：音频**播放**引擎、**编辑文档模型**、**选区模型**、**撤销/重做**、
**渲染/导出**、**格式写入**（现在只有 `timeline.py` 里一处临时 wav）。
⇒ 编辑器的四根柱子（I/O、播放、编辑模型、渲染）**目前一根都没有**。

## 4. 路线（P0→P5；每级必须"可用 + 可验证"）

| 级 | 内容 | 出口判据（可测） |
|---|---|---|
| **P0 地基** | `core/edit/`：非破坏**文档模型**（操作栈）+ **渲染引擎**（float32；重采样 soxr；抖动；写 WAV/FLAC/AIFF） | **往返测试**：读→改→写→读，未选中处**逐位不变**、选中处与预期差值在容差内 |
| **P1 播放** | 低延迟播放引擎（miniaudio/PortAudio），与视图联动（播放头/跟播） | 起播延迟、X-run 计数、设备切换不崩 |
| **P2 选区与增益** | 时间×频率**选区**（矩形→套索）；**增益**（选区衰减/增强）——最简且最有用 | 选区=矩形时与"直接对该段做增益"**逐位一致**；撤销栈正确 |
| **P3 修复算法（自研，逐个带判据）** | declip / declick / decrackle / dehum / denoise（多分辨率谱减）/ 去削波 | 每个都要先建**合成缺陷语料 + 客观指标**（SNR 提升、伪影谱），再过真素材 |
| **P4 工作流** | 批处理、宏、A/B、导出预设、动作日志导出（→"可审计"落地） | 批处理可复算；A/B 无副作用 |
| **P5 生态** | VST3/CLAP 插件、脚本、工程格式、i18n/无障碍收口 | 插件在宿主里与内核**同一结果**（互证） |

**顺序理由**：P0 是**所有**后续的地基，且**立刻可验证**；P3 的算法难度最高，放到地基与
播放稳了之后——否则会重演"先做花哨功能、判据没立"的老坑。

## 5. "极致与专业"的可测定义（不许含糊）

沿用既有纪律，给编辑部也立同类判据：
1. **无损往返**：未被编辑的采样**逐位不变**（非破坏 + 精确撤销）。
2. **测量互证**：修复后再用**同一个测量内核**量一次，证明确实只改了目标（如 dehum 后
   50/100 Hz 峰下降、其余频段差异 < 阈值）。
3. **客观指标**：每个算法有合成语料上的 SNR/SDR 提升与伪影下限，且**效果边界**写进 UI。
4. **性能**：选区操作在 X 秒素材上 ≤ Y 秒（沿用 `perf_probe` 的口径与阈值表）。
5. **可审计**：每次操作产出机器可读记录（算法/参数/依据/时间），可复算。

## 6. 非目标（明确不做，免得摊大饼）

- **不做通用 DAW**（多轨混音、MIDI、虚拟乐器、总线）。
- **不做实时处理宿主**。
- **不追全格式**：先 WAV/FLAC/AIFF；MP3/AAC 走 **ffmpeg 只读**→编辑后导出的路径。
- **不改判定内核的既有职责**：编辑器**读**测量结果，测量层**不** import 显示/编辑层（既有纪律）。

## 7. 风险（诚实，别只看好处）

- **工程量**：编辑 + 播放 + 渲染 ≈ 当前分析内核的**数十倍**；不可能一轮到位。
- **播放是独立难题**（低延迟、设备热插拔、ASIO/WASAPI 差异）。
- **听感判据难**：频谱修复的"好不好听"必须建**主客观双层评测**，否则会重演
  "假 Hi-Res 分类器"的教训（外部有效性不足就升格）。
- **许可证**：本仓已有 SBOM 纪律 ⇒ 新依赖（ffmpeg / soxr / miniaudio / VST3 SDK）的许可
  要**逐条核**并入账；GPL 传染性会影响整体授权选择。

## 8. 第一步（最小可验证增量，建议直接开工）

**不先碰 UI**，先做 **P0 的地基切片**：
一个 `core/edit/` 的**非破坏增益渲染**——读文件 → 对**时间选区**加 −X dB → 写文件，
带两条判据：
1. **往返测试**：选区外**逐位不变**（用真实曲库文件，不只合成）。
2. **与测量内核互证**：改完用现有引擎再量一次，证明**只有选中时段变**、电平差值 == X dB（容差内）。

**为什么是它**：把四根柱子里的 **I/O + 渲染**两根先立起来，**立刻可验证**、不依赖播放与 UI，
且天然产出"可审计修复"的第一条记录。

**状态**：✅ **已完成**（`core/edit/ops.py`、`render.py`、`edit_cli.py`；
判据 13 条在 `tests/test_edit_render.py`、8 条在 `tests/test_edit_cli.py`）。

### 第二步：**频域通路**（时频选区增益）—— ✅ 已完成（2026-10-18）

`core/edit/stft.py`（WOLA STFT + 覆盖守卫）+ `ops.BandGainOp` + `render.render_band`
+ CLI `--band f0-f1`。这一步的价值不只是"多一个功能"，而是**把时频编辑的效力边界量出来了**
（写出的跨度要外扩一个窗宽、float32 素材只能承诺 1 个峰值 ULP、分块不许改结果）——
三条都写进了 `docs/theory.md §12.7` 与 `CHANGELOG`，判据在 `tests/test_edit_stft.py`。

### 第三步（**已收口**）：**先建指标、再决定要不要上软掩码** —— ✅ 2026-10-18

**先建了指标**：`core/edit/metrics.py`（带内衰减实测 / 脉冲包络宽度 / SDR / 能量比——四个
都只出数、不出"好/坏"），并把"**设定 vs 实测**"写进审计与 CLI（可审计的修复）。
**再用指标做了决策实验**（`packaging/mask_tradeoff.py`，4 种掩码 × 2 种写回 × 4 列）：
谱底 −40 dB 花 20 dB 压制度买不到东西；50 ms 时间锥形花 50 ms 选区精度只换 1.6 倍包络改善；
真正需要的东西（**外扩跨度**）我们已经有了。
⇒ **结论：软掩码不进内核**（`docs/editor_research.md §7`、`docs/theory.md §12.7 ⑤`）。
⚠ 这一项在编辑升级到"**挖点/补点**"（时频修音 / declip / declick）时要**重开**。

### 第四步（**已完成**）：**P3 修复算法的判据骨架 + 第一个修复算子** —— ✅ 2026-10-18

**先建判据再写算法**（`docs/editor_research.md §8` 记全过程）：
1. `core/edit/corpus.py` —— **有真值的合成语料**：带宽已知的干净信号（`harmonic_tone` /
   `band_limited_noise`）、**硬削波三档**（`CLIP_TIERS`，severe 档饱和占比实测 22.7%，
   把 Záviška "既有基准太软"那条教训钉成语料判据）、脉冲位置已知的 `click_train`。
2. `packaging/declip_probe.py` —— **先量四种候选重建**（插值 / 样条 / Papoulis–Gerchberg /
   POCS），同一把尺子（`sdr_db` + `energy_ratio_db`）。
3. `core/edit/declip.py` + `ops.DeclipOp` + render 的 declip 路径 + CLI `--declip`：
   **POCS 三相交替投影**（带限 + 已知样本 + **削波不等式** `|x| ≥ c` 同号），**只改饱和样本**。

**这一轮的关键结果是负面的**：局部插值（工程界 Audacity ClipFix 那一族）**把 SDR 修坏**
（light 43.5→21.3、severe 10.1→1.6）⇒ **不进内核**；POCS 是四种里唯一全面提升且"带宽取窄
只退化不反伤"的 ⇒ 落地。效力边界（`B` 必须由调用方给、`B ≥ 奈奎斯特` 时逐位不变、
密集削波只 +4 dB 量级）全部写进审计与 CLI。判据 **46 条**在
`tests/test_edit_corpus.py`（20）+ `tests/test_edit_declip.py`（26），另加 CLI 侧 3 条；
编辑侧四个模块变异**逐模块 1.000**（记账见 `CHANGELOG.md` 本轮的"探针维护"一节）。

### 第五步（建议）：**给 `B` 找一个"不猜"的来源 + 密集削波那一族**

第四步把内容带宽 `B` 当**输入**收下（编辑层不估），但真实素材上 `B` 得有人量 ⇒
下一轮该做的是**测量层**的一条"内容带宽估计"（现有截止点判定器是入口），并量"估偏"对
去削波 SDR 的影响（本轮只量了"给真值 / 给窄"两种，`docs/editor_research.md §8.4`）。
同时 **severe 档（饱和 >20%）** 是本方法族的边界：要上**稀疏/相位感知**那一族
（Záviška 的 SPADE 谱系 / PHAIN 的相位约束）——**只挂账，未实现**，落地前照旧先建判据。
