## 2. 已核到的、可以直接用的结论

### 2.1 W3C《中文排版需求》（B 块：字体与排版）

> 这是一份 W3C Group Note **草案**，官方自己写明"尚未经 W3C 会员流程认可、
> 不适合正式引用"——所以下面这些结论在本项目里只作为**排版依据**，
> 不作为"标准符合性"宣称。

可直接落地的几条（均为文档明文）：

1. **汉字与标点原则上是 1:1 的正方形、无缝隙并列**。→ 界面里中文标签的行高、
   图标与文字的垂直对齐可以按"字身方格"推，不用逐像素试。
2. **四种常用中文字体各有用途**：宋体（内文/标题/注释，标题用粗）、
   楷体（公文/教科书/对话）、**黑体（标题、图说、对话中人名；内文中用较粗黑体表强调）**、
   仿宋（副标题、引言）。→ 本项目的界面全是黑体（Microsoft YaHei），
   与"标题/图说用黑体"一致；要做层级只能靠**字号 + 字距 + 颜色**，
   这与本项目"不靠字重做层级"的既有决定互相印证（本机中文字体只有 400/700）。
3. **中西文混排：横排时西文按原方向**；汉字与西文之间**用不超过 1/4 汉字宽的字距**，
   西文出现在行首行尾时**不加**额外空白。→ 我们的卡片里"采样率 / 44.1 kHz"
   这类中英混排要注意这条，不能一律加空格。
4. **不要用全角 ASCII 字符**（文档明确说：过去为整齐而用全角，
   现今应交由排版引擎处理比例/等宽字体）。→ 与 `theme.pick_text_font`
   "按内容选字体"的方向一致。
5. **破折号、省略号不得跨行断开**（界面里主要是 tooltip 与报告文本）。

### 2.2 Audacity 手册·频谱图（A 块与 C 块共用）

- **四种刻度**：Logarithmic / Mel / Bark / ERB / Period。文档解释了为什么需要：
  谐波是**线性**序列（适合线性刻度看泛音），音阶是**指数**序列（适合对数刻度）；
  Mel/Bark/ERB 在低频近似线性、高频近似对数，"把屏幕高度集中到中高频"。
  → 本项目的频谱曲线只有对数轴。**Bark 底纹不等于换刻度**（这是第五轮已记的欠账）。
- **Reassignment 算法**：文档原话是"通过按瞬时频率与群延迟的局部估计**重新定位**
  时间-频率数据，把模糊的时频数据变锐利"。→ C 块"母带/转码痕迹"可用，
  但要先验证它对我们关心的 20 Hz–20 kHz 全频段是否有意义。
- **窗型与零填充**：Hann 默认；矩形更快但泄漏严重；零填充只让颜色沿纵轴插值更细，
  **不改变**时间-频率分辨率的权衡。→ 我们频谱图用 4096 点 STFT，这一条是既有决策的依据。

### 2.3 RX / REW / SPAN（第五轮已核，此处只记与 A 块相关的）

- RX：频谱图"可点击并拖动模块进行更精确的编辑"、Spectrum 分析仪可显示
  **所选时间/频率范围的平均频谱**。→ A 块的"选区 → 给结论"有先例。
- REW：测量可"导入/导出文本"、脉冲响应可加倍频程滤波后显示、
  有完整的图形操作体系。→ A 块"导出当前视图"已经做了（PNG/JSON/CSV/HTML）。

## 3. 取不到的：改用**实测**代替引用（A 块）

matplotlib 官方文档这次没取到。但"事件会不会触发"是**可实测**的行为，
比引用更可靠——本项目本来就是"能算的绝不猜"。因此 A 块的做法是：

1. **缩放/平移的数学抽成纯函数**（`ui/zoom.py`），用单元测试钉住行为
   （对数轴下以倍率缩放、边界钳制、重置）。纯函数不依赖 Qt，测试不会偶发。
2. **事件接线用最保守的一组**：`button_press_event` / `button_release_event` /
   `motion_notify_event` / `scroll_event` / `key_press_event`。
   这些是 matplotlib 后端基类的事件名，本仓 `charts.py` 已经在用
   `motion_notify_event`（悬停 blit 就是它驱动的），所以不是新机制。
3. **滚轮事件在个别平台/离屏环境下可能不触发**——因此**必须同时给键盘缩放**
   （`+` / `-` / `0`）与双击重置。这不是备份方案，是设计要求：
   只依赖一种输入方式的交互，在另一种环境里就是坏的。
4. 交互帧时间用 `perf_probe.py` 量（新增场景 P13/P14），**不靠感觉**。

### 本轮实测到的三条（都比引用可靠，但要注意口径）

1. **缩放一格 ≈ 120 ms**（`_apply_view`，p50 119.9 / p95 128.5）。
   口径：它**包含**一次静态层重建（Bark 底纹、频段线、截止标注全部重画）。
   同样的画布只 `redraw()` 而不重建静态层是 70.5 ms——差的就是重建那 50 ms。
   → 下一步优化方向明确：把"数据层"与"视图层"拆开，缩放只碰视图层。
2. **事件本身 ≈ 0.1 ms**（`_zoom` 只改状态，重画走 28 ms 合并计时器）。
   这是"基准也会骗人"的又一例：如果量的是 `_zoom` 调用，会得到"缩放不要钱"的错误结论。
3. **悬停仍 ≈ 10 ms**（blit 快路没被缩放改动破坏）。
