# 视图覆盖矩阵与精度基线（B11-E1，实测）

> 复算：`python packaging/view_coverage.py`（`--strict` 时 720 行 @1k 行距未翻倍返回 1）。
> 样本 = **180s 立体声 44.1k 宽带噪**（"一首 3 分钟的歌"）。测的是**图实际看见
> 文件的哪一段、每列/每行多宽**——不是代码怎么写。

## ★ E1 实测纠正的两条判据（先量后改的价值）

### 1. "每列 70ms"是原始列；**显示列是 200ms**

B11 提示词写的"70ms/列"没算峰值保持压缩。实测 3 分钟歌：原始 2580 列 × 70ms
→ 显示 900 列 × **200ms**。峰值保持保住**幅度**（瞬态不丢），但时间定位就是
200ms。⇒ 精度披露必须写**显示列宽**；把 70ms 写进 UI 是不诚实的。

### 2. 360→720 行的收益在**高频**，不在低频

B11 提示词假设"50Hz 占行翻倍"——实测 **360/720 都是 7 行（倍率 1.00）**：
50Hz 附近行距（≈1Hz）本就远细于 STFT bin（10.77Hz），占行数由 **bin 泄漏
宽度**决定，翻倍行数加不了信息。

720 行的真实收益：**@1kHz 行距 19.71 → 9.79 Hz（2.01×）**——行距粗过 bin 的
高频区（插值区 546Hz 之上）垂直定位误差减半。渲染代价 1.62 → 2.00 ms
（1.24×，判据 ≤2.5×）。

⇒ **判据按实测改写**：`--strict` 检查 @1k 行距翻倍，不检查 50Hz 占行。

## 精度基线（720 行落地后的对照锚）

| 量 | 360 行 | 720 行 |
|---|---|---|
| 50Hz 占行（>峰值−40dB） | 7 | 7（bin 限制，不变是对的） |
| @1kHz 行距 | 19.71 Hz | 9.79 Hz |
| imshow（900 列，Agg 最小值） | 1.62 ms | 2.00 ms |

## 还没解决的（挂账）

* **低频 <546Hz 的"细腻"受 bin 限制**（10.77Hz@4096 窗）——根治要双分辨率
  STFT（低频用 16384 窗），动 DSP 核心，本轮只评估不实现（B11-C7）。
* 反相内容在频谱图不消失（B14 已修，`tests/test_ui_views.py` 有判据）。
