> 样本 = **180s 立体声 44.1k 宽带噪**（"一首 3 分钟的歌"）。测的是**图实际看见
> 文件的哪一段、每列/每行多宽**——不是代码怎么写。

## ★ E1 实测纠正的两条判据（先量后改的价值）

### 1. "每列 70ms"是原始列；**显示列是 200ms**

B11 提示词写的"70ms/列"没算峰值保持压缩。实测 3 分钟歌：原始 2580 列 × 70ms
→ 显示 900 列 × **200ms**。峰值保持保住**幅度**（瞬态不丢），但时间定位就是
200ms。⇒ 精度披露必须写**显示列宽**；把 70ms 写进 UI 是不诚实的。

### 2. 360→720 行的收益在**高频**，不在低频

B11 提示词假设"50Hz 占行翻倍"——实测 **360/720 都是 7 行（倍率 1.00）**：
50Hz 附近行距（≈1Hz）本就远细于 STFT bin（10.77Hz），占行数由 **bin 泄漏
宽度**决定，翻倍行数加不了信息。

720 行的真实收益：**@1kHz 行距 19.71 → 9.79 Hz（2.01×）**——行距粗过 bin 的
高频区（插值区 546Hz 之上）垂直定位误差减半。渲染代价 1.62 → 2.00 ms
（1.24×，判据 ≤2.5×）。

⇒ **判据按实测改写**：`--strict` 检查 @1k 行距翻倍，不检查 50Hz 占行。

## 色窗自适应（B11-B 落地，2026-10-16）

`_adaptive_vmin(db, db_range) = max(−db_range, p5 − 10dB)`（p5 = 矩阵 5% 分位
= 内容底）。频谱图与瀑布图同一口径。

* **用户窗（db_range）是硬上界**：自适应只单向收紧，永远不超出用户选择
  （`SPECTRO_DB_RANGE` 注释里"别做每文件自适应"的警告因此仍成立）。
* **底是量出来的**（分位），余量具名（`VDFLOOR_MARGIN_DB`）——不许造假抬高。
* ⚠ B11 提示词写 "vmin = floor + 10dB"，实测语义应为 **floor − 10**：
  窗底必须落在内容底**之下**；+10 会把内容底本身截进同一色，正是它要治的病。
* **实际窗宽印在色条标签与披露文案**（"峰值下 NdB"）——量纲必须说得出来。
* 收益：噪底高于窗底的文件不再把色阶浪费在本底上（信号纹理全色阶分辨）；
  用户放宽 db_range 时，安静尾部（低于旧固定窗的内容）显形。

## B11-C7 双分辨率 STFT 评估结论（只评估，未实现）

复算：`python packaging/lowfreq_eval.py`（两个等幅低频音的峰谷比 + 主瓣宽 +
耗时，方法论的坑记在脚本注释里：第一版谷找在"峰±40bin"里，间距小于一个 bin
时两音成一峰、谷落到旁瓣零，报出 72dB 的假"可分"——**谷必须限定在两音之间**）。

| 量 | 4096 窗（现） | 16384 窗（提案） | 改善 |
|---|---|---|---|
| Δf | 10.77 Hz | 2.69 Hz | 4× |
| 单音 -3dB 主瓣宽（Hann） | 15.5 Hz | 3.9 Hz | 4× |
| 两音可分辨间距（峰谷>3dB） | ~30 Hz | ~10 Hz | **3×** |
| 3 分钟 STFT 耗时（75% 重叠） | ~520 ms | ~550 ms | 0.92–0.98×（**不更贵**：大窗列数少） |

**结论**：

1. 低频糊的根治确实是窗长（行数治不了，E1 已证）；改善量 = 可分辨间距 3×。
2. 代价不是窗口本身（同重叠比下 ≈1×），而是**双分辨率 = 两次 pass ≈ 2× 视图
   成本**——若实现，只对 <546Hz 频段跑第二遍可以把增量压到很小。
3. **为何之前不做**：当时认为视图 STFT 与判定曲线共用 `context.spectrum()` 的
   16384 锁死口径——改视图窗等于改判定（撞宪法"结论可复算"）。但**后续核实
   两套早已解耦**（`views._stft_power` 用独立 `nperseg`，判定走 `context`
   的 16384；视图三档 2048/4096/8192 只影响看图）——前提已满足，故实现。

## 实现（C7，2026-10-16）

**做法**（`core/views.py::_dual_res_spectrogram`）：低频段（< `DUAL_RES_CUTOFF_HZ`
= 546Hz）用 16384 窗重算，与主窗（用户选的 nperseg）结果拼成**「低频细、高频粗」
的非均匀频率轴**返回。`charts._resample_rows` 用 `searchsorted(f, …)`，对**任意
单调 f** 都正确 ⇒ 低频细轴自然铺满更多显示行，真实细节进图，而非被插值抹平。

- **只动视图 STFT**：判定曲线（16384 锁死）走 `context.spectrum()`，与本处
  两套独立参数、互不影响；改视图窗不会动结论（不撞"结论可复算"）。
- **默认开、可关**：`config.dual_resolution_stft=True`；`spectrogram(dual_resolution=)`
  形参、`ViewWorker` 读 `TH.dual_resolution_stft`。`nperseg ≥ 16384` 时自动退化为
  单分辨率（避免冗余 pass）。
- **代价**：低频段多一遍 16384 窗 ≈ 一次额外 pass，总视图成本 ≈2×（可接受：
  视图算一次即缓存）。同重叠比下 16384 窗本身 ≈1× 主窗耗时（大窗列数少）。
- **判据**（`tests/test_views_dualres.py`）：① 低频带 [60,120]Hz 内频率轴 bin
  数 ≥3×；② 高频轴与单分辨率逐点一致（不引入 fake 细节）；③ 15Hz 低频间距
  双分辨率比单分辨率峰谷更深、两音间 bin 更多（真可分）；④ f 始终单调递增；
  ⑤ `nperseg≥16384` 自动关。
