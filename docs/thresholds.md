# 阈值账：区分力（C1）与出处（C2）

> 本文件是 `config.Thresholds` 的**总账**：每个字段的①区分力实测 ②出处。
> 区分力部分由 `packaging/threshold_survey.py` 产出；出处部分见 §3。

## 1. 为什么要有这份账

两条规矩（`AGENTS.md` §3.2 / §3.4）：

> **§3.4** 一个阈值如果把人全判到同一侧，它就是没用的。**新加任何阈值都要跑一次这个检验。**
> **§3.2** 每个数字标出处，二手来源标可信度。

内核审查报告（2026-10-13）指出这两条**一条都没落实**（P0-1 / P0-2）。C 块把它们补上。

**语料**：44 个**合成**文件，按每个阈值的两侧定向造样（临时目录，不入库）。
**复算**：`python packaging/threshold_survey.py`（约 19 秒）；
`--strict` 在出现"无区分力"字段时返回非 0。
**常驻判据**：`tests/test_c1_threshold_survey.py`（每次跑测试都验一遍）。

### 2.1 算法参数与判定阈值的分界

`min_drop_db` / `min_stop_db` / `cutoff_min_hz` / `cutoff_need` / `conf_slope_span`
**不定义判定**——它们决定的是"**能不能检出截止点**"。所以它们不做两侧分布检验，
只报**检出率**：合成语料 44/44 = **100 百分点**。

把它们硬塞进"两侧分布"是错的：算法参数"全落一侧"是正常现象。

### 2.2 ★ 踩坑记录：第一轮报的 5 个"无区分力"**全部**是语料造错

这一节比结论重要。

| 字段 | 第一轮报告 | 真因 |
|---|---|---|
| `bit_gap_warn` | 全落一侧 | **语料错**：`_write` 在量化**之后**又做电平归一化，而归一化乘的是非 2 的幂的因子 ⇒ **把低位重新填满**。分析器把"24bit 装 16bit"正确读成了"真 24bit"。 |
| `width_narrow_db` | 全落一侧 | **语料错（反直觉）**：`width_db = 10·log10(side/mid)`，`side=(L−R)/2`。所以让 **R 变小并不缩小 side**——`R=0.01L` 时 `side≈0.495L`、`mid≈0.505L` ⇒ width ≈ 0 dB，**根本不是单声道**。要造近单声道必须 `R = L(1−ε)`（ε=0.032 → −35.8 dB）。 |
| `lra_flat` | 只有 1 个样本有定义 | **语料错**：恒定电平的正弦算不出 LRA（`lra=None`）。必须给一点起伏（±0.4 dB 慢速调幅 → lra=0.2）。 |
| `advice_low_pct` | 全落一侧 | **语料错**：白噪的频段占比是平的，`sub+bass` 到不了 60。补一个 150 Hz 低通样本。 |
| `advice_upper_mid_pct` | 全落一侧 | **语料错**：同上，白噪的 upper_mid 恒 > 15。 |

**结论**：`Thresholds` 里**没有一个**阈值在覆盖两侧的语料上失去区分力。
但这条结论只有在**先修完语料**之后才成立——第一轮那 5 个是**假警报**。

**由此立的操作纪律**：这条判据失败时**先查语料、再查阈值**。反过来做，
就会去"调阈值"来迎合一个造错的语料——那是把测量工具往错的方向校准。
