## 1. 为什么要有这份账

两条规矩（`AGENTS.md` §3.2 / §3.4）：

> **§3.4** 一个阈值如果把人全判到同一侧，它就是没用的。**新加任何阈值都要跑一次这个检验。**

内核审查报告（2026-10-13）指出这两条**一条都没落实**（P0-1 / P0-2）。C 块把它们补上。

### 2.1 算法参数与判定阈值的分界

`min_drop_db` / `min_stop_db` / `cutoff_min_hz` / `cutoff_need` / `conf_slope_span`
**不定义判定**——它们决定的是"**能不能检出截止点**"。所以它们不做两侧分布检验，
只报**检出率**：合成语料 44/44 = **100 百分点**。

`seg_seconds` / `seg_overlap` / `seg_min_count`（C4.3 时间定位）同属这一类：
不定义判定，只影响"能不能检出问题段"。

`dual_resolution_stft`（C7）是**第三类**：连检出率都不影响，只影响频谱图画质
（视图渲染选项）。把它标成"算法参数"会让人以为它参与检出——标签必须分开。

把它们硬塞进"两侧分布"是错的：算法参数"全落一侧"是正常现象。

### 2.2 ★ 踩坑记录：第一轮报的 5 个"无区分力"**全部**是语料造错

这一节比结论重要。

| 字段 | 第一轮报告 | 真因 |
|---|---|---|
| `bit_gap_warn` | 全落一侧 | **语料错**：`_write` 在量化**之后**又做电平归一化，而归一化乘的是非 2 的幂的因子 ⇒ **把低位重新填满**。分析器把"24bit 装 16bit"正确读成了"真 24bit"。 |
| `width_narrow_db` | 全落一侧 | **语料错（反直觉）**：`width_db = 10·log10(side/mid)`，`side=(L−R)/2`。所以让 **R 变小并不缩小 side**——`R=0.01L` 时 `side≈0.495L`、`mid≈0.505L` ⇒ width ≈ 0 dB，**根本不是单声道**。要造近单声道必须 `R = L(1−ε)`（ε=0.032 → −35.8 dB）。 |
| `lra_flat` | 只有 1 个样本有定义 | **语料错**：恒定电平的正弦算不出 LRA（`lra=None`）。必须给一点起伏（±0.4 dB 慢速调幅 → lra=0.2）。 |
| `advice_low_pct` | 全落一侧 | **语料错**：白噪的频段占比是平的，`sub+bass` 到不了 60。补一个 150 Hz 低通样本。 |
| `advice_upper_mid_pct` | 全落一侧 | **语料错**：同上，白噪的 upper_mid 恒 > 15。 |

**结论**：`Thresholds` 里**没有一个**阈值在覆盖两侧的语料上失去区分力。
但这条结论只有在**先修完语料**之后才成立——第一轮那 5 个是**假警报**。

**由此立的操作纪律**：这条判据失败时**先查语料、再查阈值**。反过来做，
就会去"调阈值"来迎合一个造错的语料——那是把测量工具往错的方向校准。

### 3.2 ★ 结论：**42 个字段里只有 1 个有外部依据**

唯一一个是 `loud_war_lufs`（一手文档），而且它的依据是**推导**而非直接规定：

> **Spotify 官方支持页《Loudness normalization》**（一手）：
> 归一化目标 **−14 LUFS**（依 ITU 1770），Premium 最响档 **−11 LUFS**。
> 取 **−9 LUFS** 是因为它比该最响档**还高 2 LU** ⇒ 已超出主流平台的归一化上限。

其余 41 个**全部是工程估计**。这不是失败，是**如实记账**：

* 本项目的立场（`AGENTS.md` §3.2）是"没有出处的阈值，**宁可标'参考'也不标'判据'**"。
  所以这份账的第一价值是**不让人误以为这些数字有标准背书**。
* **"标准给出了容器规格，但没有给出判据门限"** —— 这是绝大多数条目的真实处境。
  例：44.1 kHz 采样与 22.05 kHz 奈奎斯特来自 CD 规范（IEC 60908 / Red Book）；
  但"≥21.5 kHz 算满带宽"里的 **21.5 是本项目留的余量**，没有外部出处。
* **编码器截止表**（对应 `ltd` / `lossy`）本轮**检索未取到可引用的一手表格**——
  公开可得的只有社区资料与转述，按规矩**不能拿来定阈值**，故标工程估计。
  这与 `docs/research.md` §4"有损/转码链识别"那一行"**未取到**"的结论一致。

### 3.3 用户可见处的**降级措辞**（规矩的落点）

只写进文档不算落实——**用户看得到的地方必须带限定词**：

| 位置 | 做法 |
|---|---|
| CLI 汇总 | 每次运行末尾打印：`阈值出处：42 个字段 ｜ 标准/一手文档 1 ｜ 工程估计（无出处）41`，并指向本文件（数字动态取自 `provenance_summary()`，字段增减自动跟随） |
| JSON 导出 | 结构改为 `{"threshold_provenance": {...}, "results": [...]}`——**拿到结果的人自带出处信息** |
| 设置对话框 | 每个阈值标签带 tooltip：`【工程估计，无出处】依据：…`——**手放上去就能看到**（不写在标签文字里，否则那一列读不下去） |

### 3.4 与 `docs/research.md` §4 的关系

`research.md` §4 列的是"**某个方向**需要什么文献"（四个方向，状态多为"未取到"）；
本文件列的是"**每个阈值**的出处"。两者是同一件事的**两个粒度**，
§4 保留为方向的索引，**逐条结论以本文件为准**（避免两处各说一套）。
